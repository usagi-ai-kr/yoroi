# 에이전트 협업 및 작업 분담

역할은 호스트 문서의 현재 구성을 따른다. 같은 에이전트가 오케스트레이터와 리뷰어를 겸할 수 있다.

## 역할

### 메신저

1. 사용자 요청을 컨텍스트·현 상황과 함께 오케스트레이터/리뷰어에게 전달하고 필요시 직접 처리한다.
2. 환경변수·비밀값·인프라·결정·PR 승인 등 사용자가 해야 하는 조치를 확실히 전달한다.
3. 컨텍스트를 반영한 질문 보완·상세화 외 업무는 오케스트레이터에게 위임한다.
4. 오케스트레이터의 사용량 초과로 인한 작업 불능을 확인한다. 필요시 적절한 기존 워커/리뷰어를
   오케스트레이터로 승격해 인계하며 다른 역할 재배분에도 대응한다. 모델·세션은 사용자 결정을 따른다.

### 오케스트레이터

1. 메신저의 작업을 워커에게 분배하고 자세한 요구·소유 파일·완료 기준을 docs로 전달한다.
2. 작업을 5분 안에 마칠 단위로 나눈다. 긴 테스트·빌드는 서브에이전트나 백그라운드로 유도한다.
   느린 워커의 요금제·환각·비효율·권한 원인을 확인하고 해결한다. 사용자 조치는 메신저를 통해 전달한다.
3. 리뷰어의 PR 발행 여부를 백그라운드로 감지해 작업 종료를 판정한다. 보고서 생성만으로 종료하지 않는다.
4. 가능한 작업을 쥐고 있지 않는다. 백그라운드나 일부 서브에이전트는 메신저 요청 누락 방지를 위해 허용한다.

### 워커 (2개 이상)

1. 진행 중 주요 내용은 docs에 보고하고 최종 의견·분석은 사용자 허가 범위의 issue에 남긴다.
   원격이 없거나 외부 기록이 허가되지 않았으면 호스트의 로컬 작업 기록에 남긴다.
2. 복잡한 판단은 리뷰어에게 맡기고 단위테스트·요청/문서 일치도를 먼저 확인한다.

### 리뷰어

- 워커 작업을 평가·판단하고 작은 문제는 직접 개선하거나 오케스트레이터에게 재분배를 요청한다.
- 큰 문제가 없으면 dev → main PR을 요청·발행한다. main 직접 push는 금지하며 머지는 사용자 승인을 받는다.
- issue·PR 등 외부 기록은 오케스트레이터 독점이 아니며 각 역할이 사용자 허가 범위에서 수행한다.

## 공통 제약

- 단일 파일에는 단일 소유자를 둔다. 비소유 파일은 읽기 전용이며 직접 개선도 기존 소유권을 확인한다.
- 모델·세션은 사용자가 정한다. 배정 전 실행 중 워커와 모델·상태를 확인하고 그 안에서 배정한다.
- 종료·재시작·모델 변경은 사용자 명시 요청 시에만 한다. 인계는 완료·파일·남은 작업·제약을 압축 전달한다.
- 권한·요금제 등 사용자 조치가 필요하면 메신저를 통해 전달한다. 오케스트레이터가 임의 승인하지 않는다.
- 화면을 확인한 뒤 키 입력을 한다. 환경을 잘못 바꿨으면 추가 변경하지 않고 메신저를 통해 즉시 보고한다.
- 현재 이름·라벨은 호스트 구성을 따른다. 역할 재배분으로 모델·세션을 임의 변경하지 않는다.
- 전체 대화 대신 대상 파일·인터페이스·제약만 전달한다. 미검증 CLI는 `--help`·공식 문서로 먼저 확인한다.
- 불필요한 실계정/API 중복 조회를 피하되 사용자 허가에 따른 `once` 검증은 수행한다.
- 시크릿·토큰·개인 사용량 원본은 커밋·이슈·로그에 노출하지 않는다. 합성 픽스처를 우선한다.
- memo 이슈는 사람 전용이다. 수정·생성·라벨 부착·close하지 않는다.
- 중단 요청은 해당 작업의 워커·백그라운드 실행에 전파하고 `graceful-stop` 스킬을 따른다.

## 패킷·보고·감사

1. 오케스트레이터는 docs의 상세 요구를 가리키는 패킷에 소유 파일·검증 기준·보고 경로·중단 규칙을 담는다.
   ```bash
   python3 <skill-dir>/scripts/task_packet.py create <task_id> <target_pane> <owned_files,...> <criteria,...> [report_path]
   ```
2. 워커는 소유 범위의 구현·단위 검증을 마치고 진행 docs·최종 issue·패킷의 JSON 보고서를 남긴다.
   보고서에는 변경 파일·검증 결과·막힌 원인과 역할별 조치를 구분한다.
3. 리뷰어는 보고서와 실제 diff/status를 대조해 파일 침범·시크릿·요구 충족을 평가한다.
   ```bash
   python3 <skill-dir>/scripts/report_audit.py <task_packet.json> <report.json>
   ```
   도구는 자기신고만 검사하므로 실제 변경 대조를 대신하지 않는다.
4. 오케스트레이터는 패킷·담당·상태를 한 곳에 유지하고 막힌 원인에 따라 범위·계약을 정정하거나 재분배한다.
5. 긴 대기는 백그라운드로 감시한다. 아래 도구의 보고서/blocked/한도 감지와 리뷰어 PR 발행 감시는 구분한다.
   ```bash
   bash <skill-dir>/scripts/watch_workers.sh --reports <report>... --panes <pane>... [--interval 20] [--max-polls 120] [--limit-pattern <ERE>]
   ```
   종료 코드는 감지 0, 인자 오류 2, 변화 없음 3이다. 감지 근거를 화면으로 확인하고 사용자 조치는 메신저로 전달한다.
