# 에이전트 협업 플레이북 (Coordination Playbook)

## 1. 토큰 절약 및 컨텍스트 관리 원칙
- **필수 컨텍스트 최소화**: 하위 worker에게 전체 대화록을 복사하지 않고, 작업 대상 파일, 인터페이스 계약, 제약사항만 포함된 최소 작업 패킷(Task Packet)을 전달합니다.
- **Worker 재사용과 Fresh Session 전환**: 연속된 단위 작업은 동일 Worker 세션을 재사용하여 웜업 토큰을 절감하되, 컨텍스트가 길어져 포화 상태가 되면 무리하게 늘리지 않고 구조화된 요약 Handoff를 작성한 뒤 새로운 Fresh Session으로 전환합니다.
- **요약 기반 Handoff**: 세션 교체 시 [완료된 작업 / 변경된 파일 / 남은 작업 / 불변 제약]을 압축 전달하여 기억 소실(Cold Reboot)을 방지합니다.

---

## 2. Root의 공식 명령 계약 사전 검증 책임
Root는 Worker에게 작업을 지시하기 전, 관행적 추정에 의존하지 않고 공식 1차 문서나 CLI `--help`를 직접 확인하여 올바른 명령 패턴을 제공할 책임을 집니다.

- **실제 정정 사례**:
  1. Claude Code CLI: `claude login`은 존재하지 않으며, 공식 명령은 `claude auth login`입니다.
  2. Antigravity CLI (AGY 1.3.1): `login` 또는 `auth` 하위 명령이 없으므로 `agy login`은 오류입니다. 대화형 `agy`를 단독 실행하여 브라우저/SSH 인증 안내를 따릅니다.
  3. API 키와 계정 세션의 분리: `GEMINI_API_KEY`는 별도 모델 API 모드이며, AGY 구독 quota 조회를 대체하지 않습니다.

---

## 3. 안전 및 격리 불변조건
- **배타적 소유권 (Exclusive File Ownership)**: Root는 각 작업마다 worker가 수정할 파일을 명시적으로 한정하며, worker는 소유 외 파일 수정을 엄격히 금지합니다.
- **10분 검증 단위**: 각 작업은 10분 이내에 테스트/스크립트로 증명 가능한 작은 단위로 쪼개어 전달합니다.
- **실조회와 검증의 구분**: 불필요한 계정/API 반복 조회와 모델 호출만 차단하며, 사용자 허가에 따른 `once`/`watch` 실행 검증은 막지 않고 적극 수행합니다.
- **무관용 보안**: 패킷과 보고서 모두에 시크릿 패턴(GitHub, AWS, PKCS#8, RSA 등)을 사전 차단하며, 합성 픽스처(fixture)를 우선 활용합니다.
- **End-to-End 책임과 보고 프로비넌스**: 하위 worker는 구현·테스트·검증·자체 감사를 완결하고, 보고서에 Root 조치 사항과 Worker 조치 사항을 명확히 구분(Provenance)하여 제출합니다.

---

## 4. 도구 입력 및 감사 한계 (Operational Boundaries)
- **파일 경로 기반 입력**: `task_packet.py`와 `report_audit.py`는 명시적 JSON 파일 경로 입력을 요구합니다 (stdin 파이프 불필요).
- **보고서 자기신고 한계**: `report_audit.py`는 Worker가 작성한 보고서 내용과 신고된 수정 파일의 적합성을 감사하며, OS 수준의 실시간 파일 쓰기를 물리적으로 차단하거나 미신고된 워크트리 변경을 감지하는 도구가 아님을 명확히 인지해야 합니다.

---

## 5. Worker 환경 변경 금지 사례
- "deepseek 위주로" 지시를 모델 전환 요청으로 오해해 root가 worker 세션을 종료하고 다른 모델로 재시작했습니다. 사용자의 의도는 이미 해당 모델로 실행 중인 worker를 골라 분담하라는 것이었습니다.
- 권한 프롬프트를 화면 확인 없이 키 입력으로 넘기다 입력이 모델 선택 창에 들어가 worker 모델이 바뀌었고, 이를 되돌리려 다시 재시작해 변경을 반복했습니다.
- 교훈: worker의 모델·세션·권한은 사용자 결정입니다. 기존 환경 안에서만 분담하고, 막히면 묻습니다.
