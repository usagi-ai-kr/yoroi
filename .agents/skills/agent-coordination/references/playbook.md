# 에이전트 협업 플레이북

## 1. 컨텍스트와 인계

- 메신저는 사용자 요청·현 상황을 전달하고 질문을 보완한다. 그 외 업무는 오케스트레이터에게 위임한다.
- 오케스트레이터는 docs에 상세 요구·소유 파일·완료 기준을 적어 5분 단위 패킷으로 나눈다.
- 전체 대화록 대신 대상 파일·인터페이스·제약을 전달하고 연속 단위 작업은 기존 워커를 재사용한다.
- 인계는 완료된 작업·변경 파일·남은 작업·불변 제약으로 압축한다. 세션 변경은 사용자 결정이다.
- 오케스트레이터가 사용량 초과로 작업 불능이면 메신저가 기존 워커/리뷰어 중 적절한 인원을
  오케스트레이터로 승격해 인계한다. 다른 역할 재배분도 메신저가 맡으며 모델·세션을 임의 변경하지 않는다.

## 2. 명령 계약과 파일 소유권

- 분배·전송·감사는 `coord.py`를 우선한다. 읽기 전용 조회는 직접 해도 되며 키 입력·세션 조작은 메신저에게 요청한다.

- 오케스트레이터는 지시 전 CLI `--help`·공식 1차 문서로 실제 명령을 확인한다.
- 과거 정정: Claude Code는 `claude login` 대신 `claude auth login`이었다.
- 과거 AGY 1.3.1은 login/auth 하위 명령이 없어 대화형 인증을 썼다. 현재 명령도 배정 시 재확인한다.
- `GEMINI_API_KEY`의 API 모드는 구독 quota 조회를 대체하지 않는다.
- 파일마다 단일 소유자를 정하고 비소유 파일은 읽기 전용으로 둔다. 리뷰어의 직접 개선도 소유권을 확인한다.
- 불필요한 실조회·모델 호출을 반복하지 않되 사용자 허가에 따른 `once` 검증은 수행한다.
- 시크릿·토큰·개인 사용량 원본은 커밋·이슈·로그에 노출하지 않으며 합성 픽스처를 우선한다.

## 3. 진행 보고와 리뷰

- 워커는 진행 중 주요 내용을 docs에 남기고 최종 의견·분석은 허가된 issue에 남긴다.
  원격이 없거나 외부 기록이 허가되지 않았으면 호스트의 로컬 작업 기록을 사용한다.
- 워커는 구현·단위테스트·요청/문서 일치도를 확인한다. 복잡한 판단은 리뷰어가 맡는다.
- JSON 보고서는 변경 파일·실행 검증·막힌 원인과 역할별 조치를 구분한다.
- 리뷰어는 결과를 평가하고 작은 문제를 직접 개선하거나 오케스트레이터에게 재분배를 요청한다.
- 큰 문제가 없으면 리뷰어가 dev → main PR을 요청·발행한다. main 직접 push는 금지하고 머지는 호스트 문서의 승인 규칙을 따른다.
- 외부 기록은 오케스트레이터 독점이 아니다. 각 역할은 사용자 허가 범위에서 수행하며 memo 이슈는 건드리지 않는다.
- `task_packet.py`·`report_audit.py`는 JSON 파일 경로를 받는다. stdin 파이프를 가정하지 않는다.
- 감사 도구는 자기신고의 적합성을 검사한다. OS 쓰기 차단·미신고 변경 탐지를 보장하지 않으므로
  리뷰어는 실제 `git diff`·`git status`와 대조한다.

## 4. 느린 워커와 사용자 조치

- 오케스트레이터는 요금제·환각·비효율·권한 중 느린 원인을 확인해 계약 정정·범위 축소·재분배로 해결한다.
- 환경변수·비밀값·인프라·결정·권한·요금제·PR 승인 등 사용자 조치가 필요하면 메신저가 확실히 전달한다.
- 오케스트레이터가 권한을 임의 승인하지 않는다. 사용자 모델·세션 결정을 지키며 가용 워커 안에서 재배정한다.
- “특정 모델 위주로”는 이미 해당 모델로 실행 중인 워커를 고르는 뜻이다. 종료·재시작·모델 변경 지시로 해석하지 않는다.
- 키 입력 전 화면을 확인한다. 권한 창으로 오인한 입력이 모델 선택에 들어간 사고가 있었다.
  환경을 잘못 바꾸면 복구 명목의 추가 변경을 멈추고 메신저를 통해 보고한다.

## 5. 백그라운드와 종료 감지

- 긴 테스트·빌드는 서브에이전트나 백그라운드로 유도해 오케스트레이터의 응답을 오래 막지 않는다.
- 오케스트레이터는 가능한 작업을 쥐고 있지 않는다. 백그라운드·일부 서브에이전트는 메신저 요청 누락 방지를 위해 허용한다.
- 워커 보고서 생성은 중간 신호다. 전체 작업 종료는 리뷰어의 PR 발행을 백그라운드로 감지해 판정한다.
- `scripts/watch_workers.sh`는 보고서 생성·blocked·한도 문구를 감지한다. PR 감지 기능은 없으므로
  리뷰어 PR 발행은 별도로 감시한다. PR 발행으로 머지가 승인되지는 않는다.
- 감시 대상 보고서·pane은 인자로 넘긴다. 감지 0, 인자 오류 2, 변화 없음 3으로 종료한다.
- 한도 문구는 `Free usage exceeded`·`usage limit reached`·`retrying in [0-9]`처럼 구체적으로 쓴다.
  넓은 패턴은 워커 산문에도 걸리므로 필요하면 `--limit-pattern`으로 좁힌다.
- 보고서는 전체 경로로 비교한다. blocked는 감시 대상 목록 안에서만 판정하며 `agent_status` 필드를 쓴다.
- 감지 시 실제 상태·visible 화면을 대조한다. 반복 오탐이면 보고서 생성만 기다리고 PR 감지는 별도로 유지한다.
- 작업 중 pane은 `--source visible`로 읽는다. zsh는 기본 단어 분리가 없어 전송 전 인자·내용을 검증한다.
- 감시 도구 검증은 가짜 실행기(`--herdr`)로 분기·종료 코드를 확인해 실제 에이전트 호출을 피한다.
- 중단 요청은 해당 작업의 워커·백그라운드 실행에 전파하고 `graceful-stop`에 따라 현재 상태를 보존한다.
