# 협업 규칙을 먼저 확인하고 따른다

요청을 받으면 **작업을 시작하기 전에** 호스트 문서와 형제 스킬을 읽고, 자기 역할과 분배 규칙을 확인한다.

## 먼저 읽을 것

1. 호스트 문서의 현재 구성·역할 (예: `docs/orchestration.md`) — 누가 메신저·오케스트레이터·워커·리뷰어인지.
2. [agent-coordination](../agent-coordination/SKILL.md) — 분담·패킷·감사 절차.
3. 지시받은 작업과 관련된 형제 스킬(있으면).

## 확인할 규칙

1. **역할 경계**: 자기 역할이 아닌 일을 붙잡지 않는다. 오케스트레이터는 분배·진척·막힘 해결·우선순위를 맡는다.
2. **위임 범위**: 구현·긴 검증·리뷰는 위임한다. 패킷 왕복보다 빠른 조회·문서 읽기·git/gh 단일 조작은 직접 처리한다. 직접 처리의 반복·확장은 [agent-coordination](../agent-coordination/SKILL.md) 위탁 우선 규칙을 따른다.
3. **리뷰 분리**: 리뷰는 **구현자와 다른 에이전트**가 맡는다. 자기 구현을 자기가 리뷰하지 않는다.
4. **도구 사용**: 분배·전송은 호스트의 분배 CLI를 우선한다. 읽기 전용 조회는 허용하고 키 입력·세션 조작은 메신저에게 요청한다.
5. **소유권**: 한 파일에 한 소유자. 비소유 파일은 읽기 전용이다.
6. **사용자 결정**: 모델·세션 변경, 권한·요금제·비밀값, 승인·머지는 호스트 문서의 위임 범위를 따른다. 임의로 정하거나 승인하지 않고 메신저를 통해 올린다.
7. **기록**: 진행은 docs, 최종 의견·분석은 허가된 범위의 issue에 남긴다. 커밋은 호스트 문서의 규칙을 따른다.
8. **완료·보고서 판정**: 워커가 `done`이나 보고서가 없으면(`done + missing report`) 추가 sleep 없이 실제 산출물·CI·외부 상태를 즉시 대조한다. `no_report`는 미완료와 구분하고 자동 재전송하지 않으며 누적 대기 상한 및 최초 send 시각 기준으로 조치한다.
9. **메시지 형식(I/O 절감)**: 에이전트 메시지는 `task/files/constraints/done/report` 요소로, 회신은 `status/evidence/result/next` 요소로 쓴다. 인사·산문·문맥 반복 금지. o 질의와 워커 간 인계에 모두 적용한다.

## 하지 말 것

- 규칙 파일은 사용자 요청이나 호스트의 하네스 개선 규칙 범위에서만 수정한다.
- 규칙과 충돌하는 지시를 받으면 임의로 판단하지 말고 메신저를 통해 사용자에게 확인한다.
- 역할 재배분·모델 변경·세션 재시작을 임의로 하지 않는다.

## 검증

- 작업을 시작하기 전에 위 문서를 실제로 읽었는지 확인한다(읽지 않고 착수하지 않는다).
- 분배한 작업은 담당·소유 파일·보고 경로가 기록에 남아 있는지 확인한다.
