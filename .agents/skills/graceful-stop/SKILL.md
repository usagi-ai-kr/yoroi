# 작업 중단과 재개

중단 요청은 진행 중인 모든 계획보다 우선한다. 목표는 "빨리 멈추되 부분 상태를 남기지 않기"다.

## 1. 즉시 멈춤

1. 새 명령·도구 호출·worker 지시·외부 기록(push, PR, 이슈, 배포)을 시작하지 않는다.
2. 사용자가 범위를 남겼으면("커밋까지만", "인수인계만") 그 범위만 수행한다.
3. 정리·마무리·검증 추가도 새 작업이다. 요청이 없으면 하지 않는다.

## 2. 진행 중 작업 분류

| 종류 | 처리 |
| --- | --- |
| 이미 실행된 원자적 외부 쓰기(push, merge, release, API write) | 강제 종료하지 않는다. 완료·실패만 확인해 기록 |
| 로컬 장기 실행(test, build, watch, 백그라운드 프로세스) | 중지하고 중지 사실을 기록 |
| 하위 worker | 인터럽트(Esc 등)로 중지, 새 지시 금지. 마지막 보고·변경 파일만 확인 |
| 아직 시작 안 한 후속 단계 | 시작하지 않고 "미실행"으로 기록 |

외부 쓰기를 중간에 끊으면 원격이 부분 상태가 된다. 끝나기를 기다리는 것은 중단 위반이 아니다.

## 3. 보존

- 미커밋 변경·임시 파일·브랜치·worktree를 되돌리거나 삭제하지 않는다.
- stash·reset·clean·브랜치 삭제는 사용자가 요청할 때만 한다.

## 4. 체크포인트

Git 상태를 자동 수집하고 재개 금지 표시가 있는 체크포인트를 만든다:

```bash
python3 <skill-dir>/scripts/stop_checkpoint.py create <out.md> --reason "<사유>" \
  --inflight "<작업>=<완료|실패|중지|확인필요>" --pending "<미실행 단계>" \
  --resume "<재개 조건>"
python3 <skill-dir>/scripts/stop_checkpoint.py check <out.md>
```

- 기존 파일은 덮어쓰지 않는다(`--force` 필요). 시크릿 패턴이 있으면 거부한다.
- 체크포인트 위치는 호스트 문서의 인수인계 규칙을 따른다.

## 5. 보고

멈춘 것, 실행 중이던 외부 작업의 결과, 보존한 변경, 미실행 단계, 재개 조건을 5줄 안팎으로 보고한다.

## 6. 재개

- 체크포인트의 `재개 금지`는 사용자가 명시적으로 재개를 요청할 때까지 유효하다.
- "이어서 해" 요청이라도 체크포인트의 후속 단계가 아니라 **현재 요청 범위**만 수행한다.
  남은 후속 단계는 제안만 하고 자동 실행하지 않는다.
- 상태가 `확인필요`인 외부 작업은 재개 전에 원격 상태를 다시 조회해 확정한다.
- 중지한 worker는 상태를 확인한 뒤 새 패킷으로만 재지시한다. 이전 지시를 그대로 이어가지 않는다.
