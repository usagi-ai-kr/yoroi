# 하네스 개선 절차

하네스는 에이전트의 스킬, 작업 규칙, 보조 스크립트, 운영 문서를 포괄하는 작업 환경 전체다.
작업 진행 중 관측된 문제가 발생하면 별도 사용자 지시를 기다리지 않고 즉시 진단해 최소한의 재발 방지 조치를 적용한다.

## 1. 개선 트리거 및 대상
- **트리거**: 비정상 대기(불필요한 sleep), 완료 판정 혼선, 협업 패킷 유실, 검증 누락, 권한 흐름 병목 등 실제 관측된 장애.
- **대상**: `.agents/skills/`, 규칙 문서, 보조 스크립트, 운영 가이드.
- **사용자 요청 학습**: 다른 저장소의 하네스 조사 요청은 관측 장애 없이도 수행한다. 자동 장애 조치와 구분해 아래 절차로 후보를 평가한다.

## 사용자 요청 학습 점검
1. 출처의 규칙·스킬·스크립트를 읽고 현재 호스트의 실제 절차와 대조한다. 도구의 존재와 실행 결과를 구분한다.
2. 후보별로 출처 경로·관측한 호스트 차이·적용 대상·검증 방법·채택/기존 충족/보류와 근거를 호스트 문서에 기록한다. 평가는 소유 스킬 한 곳에서 관리하고 원문은 판단에 필요한 부분만 선택해 읽는다.
3. 기존 스킬·검증기의 수정을 우선하고, 같은 규칙을 복제하지 않는다. 일반 절차와 호스트의 결정·결과는 구분한다.
4. 채택한 최소 변경을 요청 범위 안에서 구현·검증한다. 미실행·실패·제외는 통과로 기록하지 않는다.
5. 출처의 수치·모델·세션·커밋·머지 정책을 자동 승계하지 않는다. 학습 요청은 외부 쓰기나 권한 확대를 허가하지 않는다.

## 2. 기본 원칙
1. **자율 진단 및 최소 수정**: 관측 즉시 원인을 분석하고, 동일 장애의 재발을 막는 최소한의 수정만 적용한다.
2. **수정 성격에 맞는 검증**: 코드·스크립트 행동 변경은 단위/회귀 테스트를 포함하고, 문서 전용 변경은 구조·링크·줄 수 검증(호스트의 `validate-repo.py` 등)만 실행해 부작용을 확인한다.
3. **회고와 기록**: 조치 결과와 개선 내용은 관련 문서와 스킬에 명확히 기록해 후속 작업에 공유한다.

## 3. 안전 가드레일 (메타 작업 무한 반복 방지)
- **제품 목표 병행**: 하네스 개선은 실제 제품/코드 목표 작업과 병행해야 하며, 메타 작업에만 매몰되어 무한 반복하지 않는다.
- **1회 개선 루프 제한**: 단일 장애 건당 [진단 → 최소 수정 → 검증 → 기록]의 1회 루프만 수행하고 즉시 본 작업으로 복귀한다. 단, 같은 장애의 검증 실패를 교정하는 bounded 수정·재검증은 이 루프 안에서 허용한다(새 장애·범위 확장은 금지).
- **자동 장애 조치의 관측 근거 필수**: 추측이나 가상의 장애에 대한 예방적 과잉 수정은 금지하며, 실제 로그·결과가 있을 때만 자동 조치한다. 사용자 요청 학습은 위 후보 평가 절차를 따른다.
- **누적 대기 상한 준수**: 대기 지연 문제 해결 시 누적 타임아웃 상한을 두고 최초 발송 시점을 기준으로 조치한다.
- **권한 임의 확장 금지**: 하네스 개선을 이유로 승인 범위 확대, 외부 쓰기, 모델·패널 변경을 임의로 허가하거나 실행하지 않는다.
