# 목표와 버전 관리

1. 호스트 로드맵·버전 원본·기존 milestone·tag·Release를 확인한다.
   원격이 없으면 로컬 로드맵을 사용하고 원격 상태는 미확인으로 기록한다.
2. 함께 검증해야 하는 목표를 범위·완료 기준·의존성과 함께 묶고 구현 작업을 연결한다.
3. milestone 생성·수정은 요청에서 허가된 범위만 수행한다.
   완료된 목표의 범위를 조용히 바꾸거나 중복 생성하지 않는다.

## 버전

- 안정된 공개 계약 이후 호환성 파괴는 major, 호환 기능 추가는 minor, 수정은 patch다.
- `0.x`는 초기 개발 단계다. 변경 영향과 마이그레이션을 기록한다.
- minor 증가 시 patch는 0, major 증가 시 minor·patch는 0으로 초기화한다.
- minor는 정수다. `0.9.0` 다음은 `0.10.0`이다.
- 빌드 도구의 버전 원본 하나를 사용한다. 스택이 없으면 임의 버전 파일을 만들지 않는다.
- milestone은 계획, tag는 검증된 커밋, Release는 발행 기록이다.

## 릴리스 준비

1. 목표에 연결된 작업·검증·미완료 항목을 확인한다.
2. 빌드 버전·출력 버전·예정 `vX.Y.Z` tag 일치를 검증한다.
3. 실제 릴리스 커밋의 CI·통합 검증 결과를 기록한다.
4. 커밋·push·tag·Release는 호스트 규칙과 요청에 따라 수행한다.
   준비 요청만으로 발행까지 허가된 것으로 간주하지 않는다.
5. 발행 후 tag·커밋·산출물·Release 일치를 확인하고 다음 목표를 기록한다.

게시된 tag·산출물을 덮어쓰지 않는다. 검증 실패·버전 불일치 시 발행하지 않고
원인과 완료에 필요한 작업을 보고한다.
