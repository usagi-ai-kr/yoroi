# 스킬 작성과 회고

1. 호스트 규칙과 기존 스킬을 읽는다. 같은 목적이면 기존 스킬을 갱신한다.
2. 일반 절차는 스킬, 레포 경로·설정·계정·결정은 호스트 문서에 둔다.
3. 폴더와 `name`을 일치시킨다. 소문자·숫자·하이픈, 64자 이하,
   앞뒤·연속 하이픈 금지. `description`은 기능과 적용 시점을 1024자 이내로 적는다.
4. 본문에는 작업에 영향을 주는 절차·제약만 적고 사용자의 범위·권한을 확장하지 않는다.
5. 필요할 때만 상세는 `references/`, 검증은 `scripts/`, 템플릿은 `assets/`에 둔다.
   본문에서 상대 링크로 참조하고 레포 고유 값을 하드코딩하지 않는다.
6. 호스트 줄 수 제한에 맞춰 검증하고 기존 지시와 충돌하지 않는지 직접 검토한다.

## 검증

```bash
bash <skill-authoring-dir>/scripts/validate.sh <skill-dir> <max-lines>
bash <skill-authoring-dir>/scripts/check-portability.sh .agents/skills
```

Bash와 기본 유틸리티를 사용하는 구조 검사이며 전체 YAML 문법 검사는 아니다.
`check-portability.sh`는 스킬·룰에 프로젝트 고유 값(절대 경로·프로젝트명·pane id·모델·요금제 이름)이 남았는지 본다. 위반이 있으면 exit 1이고, `validate-repo.py`가 함께 실행한다.
`skills-ref`가 설치되어 있으면 추가 검증을 실행한다. 설치는 필수가 아니다.

## 회고

- 반복할 가치가 있는 실패·해결책은 관련 스킬을 갱신한다.
- 레포 사실은 호스트 문서에 기록하고 새 배움이 없으면 중복 기록하지 않는다.
- 충돌하는 지시는 교체하고 낡은 절차는 정리한다.
- 회고는 규칙 파일·외부 설정을 사용자 요청 없이 수정할 권한을 부여하지 않는다.
- 여러 에이전트가 공유하면 원본을 편집하고 상대 심볼릭 링크를 사용한다.
