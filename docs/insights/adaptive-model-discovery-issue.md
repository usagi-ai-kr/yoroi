## 2. 제안 이슈 주요 내용
- **문제 사례**: #165 Gemini 4 Argon, #167 Muse Spark Open 등 신규 공식 모델이 나와도 `src/insights/plan-catalog.ts`에 수동 하드코딩하기 전까지 레터 후보군에서 제외되는 문제 해결.
- **핵심 제안**:
  1. 공식 제공자 모델 목록/플랜 가용성 정기 갱신 및 delta 감지.
  2. 하드코딩 catalog 의존 축소 (생성형 registry/config 분리).
  3. canonical ID/cloud 태그/별칭 공식 근거 검증 (유사 모델 자동 합치기 금지, 미확인 접근권의 verified 위조 금지).
  4. 공개 벤치마크(AA, OR, OCD, Cog) 연동 및 AA 결측 시 기존 unmeasured evidence 정책 준수.
  5. 수집 실패 시 임의 갱신 배제 및 last-good 보존 (fail-closed).
- **선택 설계안**: 자동 반영 범위, #163 밴 연동, 캐시/롤백/알림 방식은 확정하지 않고 사용자 피드백 사항으로 분리.
