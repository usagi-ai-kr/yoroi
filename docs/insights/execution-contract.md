## 선택 1 — 명령·출력·종료 코드 (준비 결과 항목 1)

| 제안 | 선택 내용 | 영향 |
| --- | --- | --- |
| **1-A 확정** | `yoroi insights once [--pretty] [--refresh]`; 기본 평문, pretty는 한국어 레터. 종료 코드 성공/부분 성공 `0`, 전체 실패 `1`, 인자·설정 오류 `2` | 기존 once와 같은 종료 코드 의미. 부분 실패는 레터에 표시하며 자동화는 계속 처리 가능 |
| ~~1-B~~ 기각 | `yoroi insights [--pretty] [--refresh]`; 성공 `0`, 부분 실패 `3`, 전체 실패 `1`, 인자·설정 오류 `2` | 기각. 1-A와 달리 부분 실패 코드가 `once`와 어긋나 셸 계약이 갈린다 |

확정된 공통 제안: stdout에는 레터만, stderr에는 비밀값 없는 진단만 출력한다. 도움말·버전은 `0`, 전체 실패 때 성공 레터는 출력하지 않는다.
출력은 요약 최대 3–5개·지표/순위 표·해석과 한계·각 수치의 출처 URL/데이터 기준일·수집 시각·KST 발행일을 포함한다.
요약할 변화가 적으면 항목 수를 채우지 않고 “확인된 변화 없음/자료 부족”으로 표시한다. 전행 오류·유효 측정 0건은 소스 실패로 본다.
부분 실패는 나머지 소스의 근거를 유지한다. 모델·지표·단위·평가 버전이 다르면 합산하거나 전체 시장점유율로 설명하지 않는다.

## 선택 3 — 데이터 기준일·초기 적재·결측 (준비 결과 항목 3)

| 제안 | 선택 내용 | 영향 |
| --- | --- | --- |
| **3-A 확정** | AA/Cognition의 원자료 기준일 미상은 그대로 “미상”; 관측일 fallback으로 전일/7일 증감을 계산하지 않음 | 근거 없는 전일 비교 방지. 최신값·수집 시각은 표시하되 변화량은 `n/a: 기준일 미상` |
| ~~3-B~~ 기각 | AA/Cognition을 KST 일별 관측 스냅샷으로 비교하고 “관측일 대비 변화, 원자료 갱신일 미상”을 수치 옆에 표시 | 기각. 관측일 변화가 실제 갱신일 변화로 오독될 여지가 있어 기준일 미상을 유지한다 |

확정된 공통 제안: OpenRouter는 `metadata.date`, Arena는 `leaderboard_publish_date`를 실제 비교 날짜로 사용한다.
초기 적재는 `n/a: 이전 기록 없음`, 정확한 전일이 없으면 `n/a: 전일 결측`; 가장 가까운 과거 값을 전일로 대체하지 않는다.
7일 추세는 실제 날짜/관측 근거와 결측 수를 표시하고 보간하지 않는다. 동일 기준일 재수집은 “새 데이터 아님”으로 표시한다.
실제 기준일·UTC 수집 시각(`observedAt`)·KST 발행일을 분리한다. 현재 파서의 fallback 메타데이터는 표시/비교 계층까지 전달한다.

## 선택 4 — 일일 키·캐시·보존·재실행 (준비 결과 항목 4)

| 제안 | 선택 내용 | 영향 |
| --- | --- | --- |
| **4-A 확정** | KST 날짜당 소스별 성공 결과 재사용, 정규화 이력 90일 보존; 수동 `--refresh` 허용; 429/일시 장애 재시도 최대 1회 | 일일 호출 절약·7일 분석 여유. 같은 날짜의 실패 소스는 다음 실행에서 다시 시도 |
| ~~4-B~~ 기각 | KST 날짜당 성공 결과 재사용, 이력 30일 보존; 0.5.0에서는 강제 refresh 없이 자동 재시도 0회 | 기각. 7일 추세에 필요한 90일 보존과 수동 복구 경로를 포기한다 |

확정된 공통 제안: 캐시 키는 `(source, KST 발행일, 비밀 없는 요청 범위, schemaVersion)`이고 키·응답에 credential 원문을 넣지 않는다.
요청 범위에는 subset·기간·필터·revision·접근 tier 차이를 포함한다. 원자료 기준일은 별도 보존하며 발행일로 덮어쓰지 않는다.
성공 캐시만 재사용하고 오류는 성공으로 저장하지 않는다. 전행 실패·페이지 불완전은 새 성공 스냅샷으로 덮어쓰지 않는다.
중복 적재 키는 `(source, modelId, metric, unit, category, schemaVersion, 비교 날짜)`; 같은 날짜 갱신은 해당 일자를 갱신하고 전일 기록은 보존한다.
수동 재실행에도 동일 성공 레터를 stdout으로 다시 출력한다. “이미 전달됨”을 이유로 stdout을 비우지 않는다.
Hermes 전달 중복 키는 `(KST 발행일, 레터 내용 해시)`를 제안하며 전달 성공 확인·중복 억제·전달 재시도는 코테츠가 맡는다.
4-A의 제안 상한: 소스별 최대 10 HTTP 요청/실행(페이지·재시도 합계); Retry-After가 남은 60초 실행 예산을 넘으면 이번 소스는 중지한다.
이 상한은 quota의 대체가 아니다. 공급자별 제한도 지키고 허용된 명시적 수동 실행 외 중복 호출을 억제한다. 4-B도 요청 상한은 동일하게 제안한다.
보존 대상은 정규화 이력이며 원문 응답·HTML·credential은 저장하지 않는다. 구독 사용량의 60초 캐시/90일 상수를 자동 재사용하지 않는다.
하루가 바뀌면 새 일일 키를 사용한다. 미수집/실패 시 과거값은 기준일·지연을 표시한 참고값으로만 쓰고 최신 성공으로 가장하지 않는다.

| 제안 | 선택 내용 | 영향 |

| **5-A 확정** | 레터 문장은 **규칙 기반으로 생성**한다. LLM·외부 모델을 호출하지 않는다 | 재현 가능한 출처·수치·서식. 모델 비용·비결정성·키 관리 없음 |

## 확정 기록과 후속 준비

2026-10-11 사용자 결정으로 `1-A, 3-A, 4-A, 6-A, 8-A`와 항목 5의 규칙 기반 생성을 확정했다. 각 B안은 기각.
남은 미결정: Arena subset/수집 경로·decoder, 모델 alias·유의 변화 기준. 이 문서는 이를 확정하지 않는다.
확정된 계약을 버전 순서에 맞춰 구현 패킷으로 나누고, 합성 날짜/결측/중복/취소/권리 경계·CLI 종료 코드 테스트로 검증한다.
B안을 다시 검토하려면 별도 이슈를 만들고 새 근거를 붙인다. 문서만으로는 선택을 뒤집지 않는다.
