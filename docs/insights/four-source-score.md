# 역할별 가중 스코어 (R 1.0.2 오케 70/5/10/15·가성비 복구, 워커 4차원 p54 C 유지)

p49 "소스별 표준화 후 상위 2개 평균"과 p50 플랜별 Top3를 되돌렸고(p51), p52에서 Free 가격 강제와 균등 25%를 폐기했다. 목록은 🧭 오케스트레이터·리뷰어 Top10, 🛠️ 워커·메신저 Top10 두 개다.
구현은 `src/insights/letter-top10-score.ts`, 독립 검증은 `tests/insights-dimension-contract.test.ts`와 참조 구현 `tests/helpers/dimension-reference.ts`다.

## 사용자 결정과 구현 판단 구분

- 사용자 결정: 소스 OpenRouter·AA·Cognition FrontierCode·OpenCode Data에서 **성능·사용량·속도·가격**을 각각 표준화해 반영한다. AA가 없는 모델도 다른 근거로 평가한다. Free 경로 가격 100 강제는 폐기하고 원래 가격으로 평가한다. 가격 정보가 없는 경우에만 최저 단가 다음 점수를 준다. 두 Top10을 차별화할 가중치·기준은 에이전트가 정한다.
- R 확정(1.0.2, p75 82/6/12을 대체): 오케 성능/사용량/속도/가성비=70/5/10/15. 가성비 = AA I/(P+.01) log10 정방향(제곱 없음)·Cog USD/task 역방향, 소스별 min-max 후 차원 max, 결측 0. 상한 없이 변형별 채점 후 최고 점수 effort를 대표로 쓴다(동점 낮은 effort). p75 제거·p70 I²·p66·p56·p58·p63은 과거 정책이다.
- 워커 규칙 확정(2026-10-15 사용자 지시): p85 '사용량 0' 결정을 번복하고 성능/사용량/속도/가격 = 0.30/0.20/0.10/0.40으로 확정했다. 단 사용량 0 번복이 가산 소멸을 의미하지 않으며, **워커 가산(최대 `workerBonusCap` 5점 × mean(있는 것만: Cog correct, 사용량 표준화))은 그대로 유지**되어 기본 점수에 더해진다. `config/held-plans.json`에 등록된 플랜의 verified 모델 목록은 가격 차원에 `max(원값, p75)`(후보 풀 가격 차원의 75백분위수)를 적용하며, 혼합 단가 `(3×입력+출력)/4 > $5/M`이면 존 통과 스코어라도 ▽(미달/상한) 표기된다(단가 미상은 허용). 워커 존 임계는 0.75에서 0.60으로 완화했다(오케 0.85 유지).
- 시뮬레이션 요지: 워커 존 .60 + 보유 플랜 p75 상향 + 단가 $5/M 상한을 **모두 적용**했을 때 #144 스냅샷 기준 목표 8/8을 달성한다(p75 상향이 없거나 p50 상향이면 7/8). 여기서 '목표'는 사용자가 제시한 워커 후보 선호 계열 평가 기준(코드 규칙 아님)이다. 비용 상한 C는 [4, 6) 구간에서 동일한 결과를 유지(Kimi K3 $6이 들어오는 C≥6부터 7/8)하며 Opus 등 고단가 모델은 ▽ 처리된다.

## 차원과 소스

모든 표준화는 역할별 후보 풀(접근 가능한 paid + 런타임 검증 free 카탈로그, 최신 세대·제외 계열·후속 규칙 통과)에서 **소스마다 min-max**(0..1, 전원 같은 값이면 1)한다. 오케는 모든 평가 effort 변형을 한 풀로 표준화한 뒤 대표를 고른다. 워커 성능·사용량·AA 속도·단가는 base별 최선값을 전체 모델 풀로 표준화한다.

| 차원 | 소스(좋을수록) | 변환 | 차원 값 |
| --- | --- | --- | --- |
| 성능 | AA 역할 지표(오케·리뷰어=Intelligence, 워커·메신저=p85부터 Intelligence) · Cognition main `correct` | 선형, 높을수록 | 두 표준화 값 중 최댓값 |
| 사용량 | 오케·워커 모두 OpenRouter·OpenCode Data 토큰(오케 가중 0.05, 워커 0.20) | 양수 토큰 log10 | 역할별 최댓값(이중 가산 없음) |
| 속도 | 오케: AA 출력 tok/s · Cognition 소요 분, 워커: AA 출력 tok/s만 | 선형 | 오케 최댓값 / 워커 AA |
| price 키 | 오케 **가성비**=AA I/(P+.01) log10 정방향 · Cog USD/task 역방향, 소스별 min-max 후 max / 워커 **가격**=AA cost_per_task·total_cost 각각 log 역방향 min-max 후 평균(보유 플랜 verified 모델 max(원값, p75) 적용) | 오케 AA log10(I/(P+.01)) 정방향 · Cog USD/task 역방향 / 워커 log10(v+.01) 낮을수록 | 오케 max, 결측 0 / 워커 두 값 평균, 없으면 혼합 단가 대체(`*`), 결측 .99 |

- P는 effort별 AA 혼합 API단가 `(3입력+출력)/4` USD/1M이다. Cog 정답률은 성능에만 참여하고 Cog USD/task는 오케 가성비에만 쓴다(워커는 불참). 오케 단가는 표시·파레토용으로도 남는다.
- 오케 AA tok/s와 Cog 작업시간(분)은 각각 표준화 후 speed max. 워커 속도는 AA tok/s만. 계열별 속도·가격 정의가 다르다.
- Free는 접근 근거만으로 P를 바꾸지 않는다. P=0도 분모.01로 계산 가능. 표시 단가는 원 API 단가(없으면 `-`)다.
- **가격 결측**: AA 단가 없고 풀에 관측 단가가 있으면 워커 price:missing=.99, 풀 무가격이면0. 오케 가성비 결측은 0. 워커 price:aa는 정규화 역단가다.
- 스코어 = 100 × Σ(역할 가중치 × 차원 값) + (워커 가산: 최대 5점). **성능·사용량·속도 결측은 0점이며 가중치를 재분배하지 않는다.**

| 역할 | 성능 | 사용량 | 속도 | 가격 | 가산 |
| --- | --- | --- | --- | --- | --- |
| 오케스트레이터·리뷰어 | 0.70 | 0.05 | 0.10 | 0.15 | - |
| 워커·메신저 | 0.30 | 0.20 | 0.10 | 0.40 | 최대 5 |

- 후보 조건: 역할별 차원(오케 4·워커 4) 중 하나 이상 근거(Free 접근 행 포함). AA 결측도 다른 소스로 평가한다. 단 워커는 **AA intelligence 원값 ≥33**만 남긴다(p85; 결측은 탈락, 미달 보충도 금지). 하한 뒤 재정규화하지 않는다. 과거 0.70은 표준화 하한이었으며 p85로 폐지.
- 계열별 가격·속도 소스 정의가 다르다. p85 원값 하한 33은 AA intelligence_index 원값이며 후보 풀이 바뀌어도 기준은 변하지 않는다.

## 임계·정렬·effort

- 임계: 스코어 ≥ 후보 최고 스코어 × 0.85(오케·리뷰어) / 0.60(워커·메신저, 2026-10-15 .75에서 완화), 경계 포함. 통과 모델이 먼저 놓이고, 혼합 단가 > $5/M 초과 모델 및 임계 미달 모델은 보충(▽)으로 스코어순 배치된다. 상위 10개로 절단한다.
- 오케 추천 effort: 성능 소스에서 관측된 minimal<low<medium<high<xhigh<max 변형마다 성능·속도·가성비를 같은 effort로 평가한다(상한 없음, max·xhigh 유지 — p63 상한은 p64에서 폐기). 등급 변형이 없으면 default 단일, 등급이 있으면 default는 공유 근거만이다. 소스에 해당 effort가 없으면 단일 default/전 effort 동일값만 공유하고 나머지는 결측0이다. 전 변형 풀 표준화 후 R 점수(70/5/10/15) 최고를 대표로 고르며 동점은 낮은 effort다. 임계·순위는 대표 점수로 계산한다.
- 워커 추천 effort: 성능 차원을 낸 소스(동점 AA)의 최고 effort이며, AA 속도 최대·단가 최소는 base 최선값을 유지한다.
- GPT-6.1 Sol과 GPT-6 Sol은 독립 후보이며 두 모델 사이 세대 제외·후속 관계·점수 복사를 적용하지 않는다(2026-10-14 사용자 결정).
- 전역 Free-only 제외는 폐기했다. Free 모델도 전체 Top10에 들어간다(Free 별도 섹션은 유지 가능, 접근 근거만 담당). 두 목록 사이 강제 배제·quota는 없다.
- **표시 보정(R 확정)**: raw 점수는 I 선형 가중합 그대로다. 표시 점수는 역할별 전체 적격 대표 모델의 raw를 midrank 정규 순위(50중심·SD 약10)로 변환한 값이며, Top10 컷·▽·존 판정은 raw 기준을 유지한다. finite만 모집단, n=0은 빈 배열, n=1·전부 동점은 50, 동점은 midrank 근사.

## 해석상 주의

- 오케는 단가가 점수에 참여하므로 비싼 고성능 모델도 가성비로 조정된다(R). 워커 가격은 성능과 무관한 단가 점수이며 결측.99 우대는 별도 한계다.
- Cog 시간 결측은 오케 speed에 영향을 준다. 오케·워커 모두 OR/OCD 사용량에 기여한다(오케 0.05). 정규화는 관측값만으로 계산하고 결측0을 anchor로 넣지 않는다.
- 가중치 실효 영향은 차원별 분산에도 좌우된다. 워커 품질 하한은 빠르고 싼 저성능 모델의 보충 진입도 막는다. 가격 결측 0.99 우대는 별도 한계로 유지한다.

## 과거 독립 검증 p52 (아래는 p54 이전 결과·정책 이력)

- 입력 `/tmp/yoroi-p52-runtime-input.json`(AA 1506·Cognition 280·OR 50·OCD 9·검증 free 11). 독립 참조 구현과 core 재계산이 순서·스코어·effort·차원 4값·`sources`(`price:missing` 포함)·`dimensionSources`까지 일치한다(불일치 0). 최종 가중치로 재생성된 o1 결과 `/tmp/yoroi-p52-result.json`(두 목록 10행)도 모두 일치한다.
- 두 목록 교집합: **p51 원본(Free 가격 1+균등) 7/10 → p52 가격만 수정+균등 9/10 → 초안(70/10/5/15, 20/20/35/25) 7/10 → 최종 4/10**. 같은 가격 정책 baseline 대비 9→4, p51 원본 대비 7→4다. Top3는 p51 두 목록 모두 muse-spark·Sonnet·Opus에서 오케 Opus·Sonnet·gpt-6-1-sol / 워커 Sonnet·ling-3-0-flash-fin·Opus로 갈린다. 공통은 Opus·Sonnet·Haiku·muse-spark 4개다. 근거는 오케 판단·검토 성능 75%, 워커 실행 속도 50%·경제성 25%, 중복 quota·강제 배제 없음이다.
- 부작용: 오케는 임계 통과가 3개뿐(▽ 7개)이고 Luna는 워커 11위로 Top10 밖이다. 워커 평균 성능 기여가 8.8/15라 성능이 낮은 모델(gpt-oss-20b 등)이 속도·가격으로 오른다.
- 가격 출처: Top10 가격 기여는 Claude·Luna가 Cognition cost, 나머지가 AA 단가에서 오며 척도가 달라 섞이는 한계가 있다. 결측 0.99 후보 6개(Free-only 3 포함)는 Top10 밖(최고 오케 30위·워커 23위)이며 결측을 0으로 바꿔도 Top10은 같다. 단가를 숨긴 모델이 거의 손해를 보지 않는 잠재 부작용(워커 가격 가중 25%)은 남는다. 상세는 p52 감사 기록.
- Free-only 후보(Free 접근 행만 있는 모델)도 후보로 포함해 후보 39개 전체의 순서·점수·belowZone이 core와 일치한다(점수 오케 9.9·워커 24.75, 가격 0.99, Top10 밖).
- 재현: 독립 감사 스크립트 실행(환경변수 `P52_INPUT`·`P52_RESULT`로 입력·o1 결과 지정).

## 검증과 회고

- `insights-c-policy.test.ts`·`insights-dimension-contract.test.ts`는 effort 정합·다른 effort fallback 금지·워커 Cog 시간/비용 불참·전체 풀 정규화 후 하한·정확히 33 경계 포함을 검증한다(p85).
- `insights-free-global-top10.test.ts`: Free 접근만으로 오케 후보는 유지하되, 워커 성능 하한을 우회하지 못한다. 관측 단가0과 워커 가격결측.99를 구분하며 오케는 가격이 점수에 불참한다.
- 서로 다른 effort의 성능·비용·속도를 합치면 실제 실행으로 달성할 수 없는 점수가 된다. 가중치 조정에 앞서 effort와 소스 단위·모집단의 비교 가능성을 먼저 점검한다.
