# 역할별 가중 스코어 (p75 오케 82/6/12·가성비 제거, 워커 4차원 p54 C 유지)

p49 "소스별 표준화 후 상위 2개 평균"과 p50 플랜별 Top3를 되돌렸고(p51), p52에서 Free 가격 강제와 균등 25%를 폐기했다. 목록은 🧭 오케스트레이터·리뷰어 Top10, 🛠️ 워커·메신저 Top10 두 개다.
구현은 `src/insights/letter-top10-score.ts`, 독립 검증은 `tests/insights-dimension-contract.test.ts`와 참조 구현 `tests/helpers/dimension-reference.ts`다.

## 사용자 결정과 구현 판단 구분

- 사용자 결정: 소스 OpenRouter·AA·Cognition FrontierCode·OpenCode Data에서 **성능·사용량·속도·가격**을 각각 표준화해 반영한다. AA가 없는 모델도 다른 근거로 평가한다. Free 경로 가격 100 강제는 폐기하고 원래 가격으로 평가한다. 가격 정보가 없는 경우에만 최저 단가 다음 점수를 준다. 두 Top10을 차별화할 가중치·기준은 에이전트가 정한다.
- p75 확정(2026-10-14, p70 70/5/10/15를 대체): 오케 가성비를 제거하고 성능/사용량/속도=82/6/12(70:5:10 비례 재배분, 사용량은 워커와 같은 OR·OCD 토큰)로 둔다. 상한 없이 변형별 채점 후 최고 점수 effort를 대표로 쓴다(동점 낮은 effort). p66 가성비(AA I²/P·Cog USD/task max)·p70 70/5/10/15·p56 F(90/0/2.5/7.5)·p58 P1(95/0/2.5/2.5)·p63 상한(high 이하)은 과거 정책이다. 워커 0.375/0/0.125/0.5·AA intelligence 원값 33 하한·가격 AA 2종 log 평균·가산 최대 5점(p85).

## 차원과 소스

모든 표준화는 역할별 후보 풀(접근 가능한 paid + 런타임 검증 free 카탈로그, 최신 세대·제외 계열·후속 규칙 통과)에서 **소스마다 min-max**(0..1, 전원 같은 값이면 1)한다. 오케는 모든 평가 effort 변형을 한 풀로 표준화한 뒤 대표를 고른다. 워커 성능·사용량·AA 속도·단가는 base별 최선값을 전체 모델 풀로 표준화한다.

| 차원 | 소스(좋을수록) | 변환 | 차원 값 |
| --- | --- | --- | --- |
| 성능 | AA 역할 지표(오케·리뷏어=Intelligence, 워커·메신저=p85부터 Intelligence) · Cognition main `correct` | 선형, 높을수록 | 두 표준화 값 중 최댓값 |
| 사용량 | 오케·워커 모두 OpenRouter·OpenCode Data 토큰(오케 가중 0.06) | 양수 토큰 log10 | 역할별 최댓값(이중 가산 없음) |
| 속도 | 오케: AA 출력 tok/s · Cognition 소요 분, 워커: AA 출력 tok/s만 | 선형 | 오케 최댓값 / 워커 AA |
| price 키(워커만) | 워커 **가격**=AA cost_per_task·total_cost 각각 log 역방향 min-max 후 평균 (오케는 가성비 제거, p75; p85) | 워커 log10(v+.01) 낮을수록 | 두 값 평균, 없으면 혼합 단가 대체(`*`), 결측 .99 |

- P는 effort별 AA 혼합 API단가 `(3입력+출력)/4` USD/1M이다. Cog 정답률은 성능에만 참여하고 Cog USD/task는 어느 역할 점수에도 쓰지 않는다(오케는 p75로 제거, 워커는 원래 불참). 오케 단가는 표시·파레토용이다.
- 오케 AA tok/s와 Cog 작업시간(분)은 각각 표준화 후 speed max. 워커 속도는 AA tok/s만. 계열별 속도·가격 정의가 다르다.
- Free는 접근 근거만으로 P를 바꾸지 않는다. P=0도 분모.01로 계산 가능. 표시 단가는 원 API 단가(없으면 `-`)다.
- **워커 가격 결측만 .99**: AA 단가 없고 풀에 관측 단가가 있으면 price:missing=.99, 풀 무가격이면0. 오케는 가격 차원이 없어 `price:*` 소스·`dimensionSources.price`가 비고 cost 성분은 0이다. 워커 price:aa는 정규화 역단가다.
- 스코어 = 100 × Σ(역할 가중치 × 차원 값). **성능·사용량·속도 결측은 0점이며 가중치를 재분배하지 않는다.**

| 역할 | 성능 | 사용량 | 속도 | 가격 |
| --- | --- | --- | --- | --- |
| 오케스트레이터·리뷰어(가격 열 없음) | 0.82 | 0.06 | 0.12 | - |
| 워커·메신저 | 0.375 | 0 | 0.125 | 0.5 |

- 후보 조건: 역할별 차원(오케 3·워커 4) 중 하나 이상 근거(Free 접근 행 포함, 오케는 단가 근거만 있어도 후보이나 점수에는 불참). AA 결측도 다른 소스로 평가한다. 단 워커는 **AA intelligence 원값 ≥33**만 남긴다(p85; 결측은 탈락, 미달 보충도 금지). 하한 뒤 재정규화하지 않는다. 과거 0.70은 표준화 하한이었으며 p85로 폐지.
- 계열별 가격·속도 소스 정의가 다르다. p85 원값 하한 33은 AA intelligence_index 원값이며 후보 풀이 바뀌어도 기준은 변하지 않는다.

## 임계·정렬·effort

- 임계: 스코어 ≥ 후보 최고 스코어 × 0.85(오케·리뷰어) / 0.75(워커·메신저), 경계 포함. 통과 모델이 먼저, 미달은 보충(▽)이며 스코어순, 동점은 모델명 오름차순이다. 상위 10개로 절단한다.
- 오케 추천 effort: 성능 소스에서 관측된 minimal<low<medium<high<xhigh<max 변형마다 성능·속도를 같은 effort로 평가한다(상한 없음, max·xhigh 유지 — p63 상한은 p64에서 폐기). 등급 변형이 없으면 default 단일, 등급이 있으면 default는 공유 근거만이다. 소스에 해당 effort가 없으면 단일 default/전 effort 동일값만 공유하고 나머지는 결측0이다. 전 변형 풀 표준화 후 p75 점수(82/6/12) 최고를 대표로 고르며 동점은 낮은 effort다. 단가는 대표 선택에 쓰지 않는다. 임계·순위는 대표 점수로 계산한다.
- 워커 추천 effort: 성능 차원을 낸 소스(동점 AA)의 최고 effort이며, AA 속도 최대·단가 최소는 base 최선값을 유지한다.
- GPT-6.1 Sol과 GPT-6 Sol은 독립 후보이며 두 모델 사이 세대 제외·후속 관계·점수 복사를 적용하지 않는다(2026-10-14 사용자 결정).
- 전역 Free-only 제외는 폐기했다. Free 모델도 전체 Top10에 들어간다(Free 별도 섹션은 유지 가능, 접근 근거만 담당). 두 목록 사이 강제 배제·quota는 없다.

## 해석상 주의

- 오케는 단가가 점수에 불참하므로 비싼 모델도 성능만으로 상위에 오른다(저가 우대 없음, p75). 워커 가격은 성능과 무관한 단가 점수이며 결측.99 우대는 별도 한계다.
- Cog 시간 결측은 오케 speed에 영향을 준다. 오케·워커 모두 OR/OCD 사용량에 기여한다(오케 0.06). 정규화는 관측값만으로 계산하고 결측0을 anchor로 넣지 않는다.
- 가중치 실효 영향은 차원별 분산에도 좌우된다. 워커 품질 하한은 빠르고 싼 저성능 모델의 보충 진입도 막는다. 가격 결측 0.99 우대는 별도 한계로 유지한다.

## 검증과 회고

- `insights-c-policy.test.ts`·`insights-dimension-contract.test.ts`는 effort 정합·다른 effort fallback 금지·워커 Cog 시간/비용 불참·전체 풀 정규화 후 하한·정확히 33 경계 포함을 검증한다(p85).
