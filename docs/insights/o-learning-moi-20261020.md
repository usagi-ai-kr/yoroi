## (1) 직접 vs 위탁

- o 직접: 단위 선정·분할(10~15분, 소유권 비중첩), 브리프, 디스패치,
  콜백 수신, 수락 판정(산출물 검사+게이트+diff), 커밋·push·PR·squash,
  이슈 코멘트, 사용자 보고.
- 위탁: 구현·테스트·조사측정·스크린샷·배포 runbook·교차리뷰·하네스 수정.
- 실례: 오전 직접 수정 6~7건 반성 → 오후부터 작성자 수정 라운드(최대 2회).

## (2) 패킷은 o가 쓴다

- 브리프 작성·전송은 o 담당(AC·소유·금지·검증 고정이 판단 핵심).
- 줄인 방법: 브리프 템플릿화, 리뷰 브리프는 기준만 교체 재사용.
- 다음: 리뷰 체인 도입 시 리뷰 패킷 전송만 워커가 한다.

## (3) 책임 분담

- 콜백: 워커가 완료·blocked·failed 시 o 패널에 prompt 전송, o는 폴링 안 함.
- 상태 감시: 단위 묶음당 폴백 타이머 1개, 울리면 누락분만 triage.
- 집계: o. 리뷰: r(작성자와 다른 모델). 커밋·PR·병합: o.

## (4) 직접 일 줄인 실례 3개

1. `--wait` 폴링 → 워커 콜백 + 폴백 타이머 1개 (agy 오감지 해소).
2. 리뷰 차단 직접 수정 → 작성자 수정 라운드, o는 재리뷰+게이트만 확인.
3. Lighthouse·스크린샷·배포 runbook 전부 워커 단위, o는 보고서·PNG만 확인.
