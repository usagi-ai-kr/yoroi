# p65 분배 (2026-10-14 사용자 결정)

p64 구현은 멈추지 않는다. 의견은 구현을 막지 않는다. 최종 가중치·결합 채택은 사용자다. 메신저(코테츠)에게 올린다.

## 1. 가중치 외부 설정 (w2)

- 오케·워커 차원 가중치를 코드 상수에만 두지 않는다.
- 형식은 JSON. 근거: 2역할×4차원표는 환경변수로 읽기 어렵고, YAML은 새 의존이다.
- 경로 `config/score-weights.json`. 키는 `orchestrator`·`worker` 아래 `performance` `usage` `speed` `price`.
- 저장소 기본값: 오케 0.70/0/0.15/0.15, 워커 0.30/0.20/0.10/0.40. 파일 없으면 이 기본값. 값 오류(숫자 아님, 음수, 합이 1이 아님, 모르는 키)는 예외로 멈춘다. 조용히 무시하지 않는다.
- 키·경로는 `docs/insights/score-weights.md`. 테스트로 파일 값과 기본값이 같음을 고정한다.
- 의견이 달라도 기본 파일은 위 값으로 둔다. 사용자가 바꾸기 전에 숫자를 바꾸지 않는다.

## 2. 가성비 결합 (w2 구현, w1 순위)

- (a) AA `I²/(P+0.01)` 와 (b) Cognition USD/task 를 택일하지 않는다.
- 제안 결합: 소스마다 min-max한 뒤 차원 max. (a)는 높을수록, (b)는 낮을수록. 원값을 더하지 않는다.
- 제품은 이 결합으로 진행한다. w1은 단독 (a)·단독 (b)·결합의 오케 순위 차이를 보고한다. 채택은 사용자.

## 3. 의견 (w1~w4 각 1회)

- 대상: 오케 70/0/15/15. 찬성 또는 수정안과 근거. 한 파일에 한 명.
- 구현·리뷰를 멈추고 의견만 쓰지 않는다. w4는 구현하지 않고 의견+리뷰만.
