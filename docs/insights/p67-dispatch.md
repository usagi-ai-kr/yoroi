# p67 분배 (2026-10-14, 민감도보다 우선)

오케 usage 0 결정을 바꾼다. 사용량을 적절히 반영한다. 확정 숫자는 사용자가 정한다. 그 전에 가중치 파일을 바꾸지 않는다.

## 격자 (w1, p66 무usage 격자보다 우선)

- 기준선 70/0/15/15를 반드시 넣는다.
- 성능 기준 P={0.60,0.65,0.70,0.75,0.80,0.85,0.90,0.95,1.00}, usage U={0,0.05,0.10,0.15}.
- 실제 성능=P−U. usage를 올린 만큼 성능만 줄인다. 속도+가성비 합은 1−P로 유지한다.
- 그 합의 배분 3축: 균등, 속도 2/3, 가성비 2/3. 합이 0이면 한 칸.
- 칸마다: Top3가 기준선과 같은지, medium·high·max 비중, 비허용 max 건수(flash/free·free접근·혼합단가≤0.50 제외), 임계 통과 수.
- 추천 usage 1개와 근거. 0도 허용. 파일에 쓰지 않는다.
- 오케 레터에 사용량 열을 다시 넣을지 판단만 보고한다. 표시 코드는 바꾸지 않는다.
- 미제출 p66 무usage 표는 버려도 된다. 이미 낸 U=0 표는 이 격자의 U=0 슬라이스로 쓴다.

## 문서 (w2)

- `docs/insights/score-weights.md`에 오케 usage와 워커 usage 0.20의 해석 차이만 추가한다.
- 워커 0.20은 성능 하한 통과 모델의 주요 선택 근거. 오케 usage는 판단 성능을 뒤집지 않는 가벼운 조정이다. 소스는 같게 OR·OCD 토큰이나, 제품 활성화는 확정 전 하지 않는다.
- `config/score-weights.json` 숫자 변경 금지. 결합 확정 반영이 끝나지 않았으면 이어서 하고, usage 숫자 확정 문구는 넣지 않는다.
