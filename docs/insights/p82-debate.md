# p82 토론: 워커 스코어 설계 (2026-10-14 사용자 지시 "워커들이랑 잘 토론해봐")

o는 분배·정리만 맡는다. 결론을 한 사람이 내지 않는다. 결과: `scratch/reports/yoroi-p82-debate.md`(o, 라운드별·원문 경로 포함).
제품·설정 값 변경은 사용자 결정 뒤에 한다. 커밋·push 금지.

## 입력 (저장본 기준 계산 결과, 같은 입력·렌더 경로)

- p79 가격 가중: `scratch/reports/yoroi-p79-w1s-table.md`(S1), `yoroi-p79-w2v-report.json`(S2 검증)
- p80 멤버십 규칙: `yoroi-p80-w4d-report.json`(D1 진단), `yoroi-p80-w2c-table.md`(C2), `yoroi-p80-w4v-table.md`(V3)
- p81 AA 비용·소스 조합: `yoroi-p81-w1k-table.md`(K1), `yoroi-p81-w3k-table.md`(K3), K2 검증(있으면)

## 질문 (모든 워커 공통)

1. 워커 가중치는 현재 30/20/10/40, p79 후보 A 25/15/10/50, D 30/15/5/50 중 무엇이 맞는가? 다른 값이면 근거를 댄다.
2. 워커 성능 하한은 현행(표준화 0.70), 원값 하한(임계 몇), 다른 규칙 중 무엇인가? ▽ 보충 자격은 바꿔야 하는가?
3. 워커 가격 근거는 현행, AA cost_per_task·total_cost 단독, 결합, 대체 중 무엇인가? 결측 모델은 어떻게 처리하는가?
4. 차원별 소스 조합은 무엇인가? 성능·사용량·속도(tok/s·TTFT·end-to-end, 평균 vs max)·Cog 포함 여부를 답한다.
5. 오케(82/6/12)에도 같은 소스 조합을 적용해야 하는가? 근거만 쓰고 결론은 선택지로 둔다.

## 토론 규칙 (모든 패킷에 그대로 넣는다)

- 모델 이름을 조건에 넣는 조정은 금지한다(과적합). 근거는 데이터 요건·결측·표본·안정성으로만 댄다.
- 근거 없는 주장은 채택하지 않는다. 수치에는 저장본 기준과 재현 경로(보고 파일·파일:줄)를 붙인다.
- 결론이 갈리면 어느 파라미터에서 뒤집히는지(경계 민감도)를 적는다.
- 계산·문서 수준에서만 토론한다. config·src는 수정하지 않는다.
