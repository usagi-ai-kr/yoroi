## X2 요구 (사용자 보충: "이거 3개에다가 '있다면' 가산점 형태로 frontier code와 사용량을 사용", X 보고 후 다른 워커)

- 기본 근거는 AA 3개다.
  - 성능: `artificial_analysis_intelligence_index`
  - 가격: `intelligence_index_cost_per_task`, `intelligence_index_total_cost`
- 가산: FrontierCode(Cog correct·new_score)와 OR·OCD 사용량은 값이 있으면 보너스로 더한다. 값이 없으면 감점·탈락시키지 않는다(기본 점수 유지).
- 차원별 정규화를 따로 한다. cost_per_task와 total_cost는 개념·단위가 달라 원단위로 합산하지 않는다(각각 단독·소스별 정규화 후 max·평균 후보).
- 보너스 합성식 후보 2~3개를 비교한다(예: 기본 점수 + b×보너스 정규화값, b 상한 5·10·15점). 보너스 최대 영향도를 수치로 보인다.
- 모든 모델에 같은 규칙을 적용한다(이름 조건 금지).
  - 워커 Top10 멤버십·순위·🆕/🚪·파레토, 현행 대비 차이
  - 보너스 있음/없음 비교(mimo-v2-6-flash 포함)
  - 상한 ±5점 민감도
- 추천 1개(합성식·상한·결측 정책)와 근거를 붙인다. `yoroi-p84-mimo-aa-observed.md`에 합쳐 기록한다(100줄 이하, 넘치면 `-x2.md` 분리).
- 보고 `yoroi-p84-x2-report.json`. config·src 변경 금지.

## M1 요구

- 워커 후보 풀(하한 판정 전 전체)에서 차원별(성능·사용량·속도·가격) 결측을 세고 원인을 나눈다.
  - (a) 소스가 해당 metric을 제공하지 않는다.
  - (b) 모델별 관측이 누락됐다.
  - (c) 모델·effort가 비호환이거나 지표가 적용되지 않는다.
  - (d) 수집 오류다(부분 수집·거절 행).
- 결측별로 대체 가능한 같은 의미의 다른 소스나 다른 effort 관측이 있는지 표시한다. 다른 소스는 AA intel/coding/agentic, Cog correct·new_score, AA cost_per_task·혼합 단가, tok/s·TTFT·e2e다.
- 원인 판정 근거는 저장 payload 필드·행 수·파일:줄로 적는다.

## M2 요구 (M1 보고 후)

- 후보:
  - Z0 현행: 결측 0, 가격 결측 .99
  - Z1 중앙값 채움
  - Z2 근거 대체
    - 순서: 같은 의미 다른 소스 → 같은 모델 다른 effort(불확실 표시) → 같은 소스 보수적 분포값(예: 하위 25%)
    - 신뢰도 감점: 대체 단계별 계수(예: 1.0/0.9/0.8)
  - Z3 근거 대체이지만 감점 없음
- 차원 간 대체는 금지한다(성능↔가격↔속도).
- 각 후보를 p79 A·p80 B'(40~45)·p81 ④와 조합해 계산한다.
  - 워커 Top10 멤버십·순위·🆕/🚪·파레토
  - 결측률 보완 전후, 표본 수
  - 원 관측과 보완값 분리 표기 방식(예: `71*`, 각주에 출처)
- 감점 계수 ±0.05, 분포 분위 ±10%p에서 멤버십이 유지되는지 경계 민감도를 본다.
- 식·소스·관측 수·불확실성 표기를 표에 남긴다(100줄 이하). 추천 1개와 근거 3줄, 선택지와 영향을 붙인다.
