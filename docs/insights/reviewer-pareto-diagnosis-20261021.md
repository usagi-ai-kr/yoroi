## 1. 코드 확인

`src/insights/letter-reviewer-pareto.ts`:
- 지배 규칙 ✓: `other.score >= self.score && other.cost <= self.cost && (other.score > self.score || other.cost < self.cost)` ✓ (strict 1개 ✓ · 양쪽 동점은 비지배 ✓).
- 결측 ✓: score·cost 중 하나라도 유한하지 않으면 **비파레토 처리** ✓ · 결측 후보는 다른 후보를 지배하지도 않음 ✓.
- 축 ✓: score↑ + **원시 비용↓**(정규 price 는 역방향이라 사용 안 함 ✓) · 비용 = `effectiveCost ?? blendedCost` ✓.

`src/insights/letter-reviewer-candidates.ts`:
- 후보는 **3차원(성능·속도·가격) 완비**만 통과 ✓ → **가격 결측 변형은 후보에서 제외**됨 ✓(excluded: `missing reviewer evidence: price`) ✓.
- → 실제 후보 풀에는 **비용 결측이 존재하지 않는다** ✓ ⇒ 파레토 모듈의 "결측 ⇒ 비파레토" 분기는 **실 경로에서 도달 불가** ✓ ⇒ #241 의 1행은 결측 탓이 아님 ✓.
