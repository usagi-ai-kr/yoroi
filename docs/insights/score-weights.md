# 점수 가중치 외부 설정 (config/score-weights.json, p65 2026-10-14, p75 오케 가성비 제거)

- 경로·키: 저장소 루트 `config/score-weights.json`. 최상위 `orchestrator`·`worker`, 각 아래 오케는 `performance`·`usage`·`speed` 세 키, 워커는 `price`를 더한 네 키(p75: 오케에는 `price` 키가 없다).
- 저장소 기본값(p85 확정): 오케 0.82/0.06/0.12(p70 70:5:10을 비례 재배분, 가성비 제거), 워커 0.375/0/0.125/0.5(성능/속도/가격, 사용량은 가산으로 이동). **파일이 없으면 이 기본값**을 쓴다.
- 값 오류는 조용히 무시하지 않고 예외로 멈춘다: JSON 파싱 실패, 모르는 역할·차원 키(오케 `price` 포함), 역할별 차원 누락, 숫자 아님, 음수, 역할별 합 ≠ 1(허용오차 1e-9).
- 로더: `src/insights/letter-top10-score-weights.ts`(`loadScoreWeights`·`validateScoreWeights`·`SCORE_WEIGHTS`).
  정책 상수 `ROLE_DIMENSION_WEIGHTS`(`letter-top10-score-policy.ts`)가 코드 리터럴이 아니라 이 값을 그대로 쓴다.
  스코어·레터 표시 문구가 같은 값을 본다.
- 바꾸는 방법: 파일 숫자만 고친다. 코드에 숫자를 복사하지 않는다. 지금은 파일 값=기본값이며 사용자가 확정하기 전까지 바꾸지 않는다.
  `tests/insights-score-weights.test.ts`가 파일 값=기본값, 파일 없음=기본값, 잘못된 값 예외, 로더 사용을 고정한다.
- 형식 근거(사용자 결정): 역할별 차원 표는 환경변수로 읽기 어렵고 YAML은 새 의존이라 JSON을 쓴다.
- **오케 가성비 제거(p75 사용자 지시)**: p66의 오케 가성비(AA `I²/(P+0.01)`·Cognition USD/task)를 스코어에서 뺐다. 오케 단가는 표시·파레토용으로만 남고
  `sources`에 `price:*`가 없다. 워커 `price`(AA 혼합 단가, 결측 .99)와 파레토 열(단가 대비 스코어)은 그대로다.

## 오케 usage 0.06 vs 워커 사용량 가산 이동 (p67 해석, p70 확정, p75 재배분, p85 가산 이동)

- 워커(p85): 사용량은 기본 차원에서 빠지고 **가산(bonus)**으로 이동했다. 가산 = `workerBonusCap`(최대 5점) × mean(있는 것만: Cog correct 표준화, 사용량 표준화). 없으면 0이고 탈락시키지 않는다.
- 오케 0.06: 판단·계획 역할에서는 사용량이 **판단 성능을 뒤집지 않는 가벼운 조정**으로만 쓰인다. 성능 82%를 두고 나머지 18%를
  사용량·속도에 6/12로 나눠, 같은 판단 성능대에서 빠르고 가벼운 쪽을 소폭 우대한다(가성비 없음).
- 소스는 두 역할 모두 OR·OCD 토큰으로 같다(`ROLE_SOURCES`의 `usage` — p70에서 오케도 켰다). 다른 것은 가중치와 역할 목적뿐이다.
- 상태: p85 확정으로 오케 0.82/0.06/0.12, 워커 0.375/0/0.125/0.5 + workerBonusCap 5(파일·코드 기본값 동일). 숫자 변경은 사용자 결정으로만 한다.
