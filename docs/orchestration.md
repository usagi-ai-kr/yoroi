# 협업 분담·중단 (레포 전용 값)

일반 절차는 스킬을 따른다. 이 문서는 현재 pane·모델·역할과 레포 운영 값을 기록한다.

- 분담·패킷·감사: [agent-coordination](../.agents/skills/agent-coordination/SKILL.md)
- 중단·체크포인트·재개: [graceful-stop](../.agents/skills/graceful-stop/SKILL.md)

## 현재 구성 (2026-10-21)

메신저는 코테츠다. 사용자가 오케스트레이터에게 직접 지시하면 메신저 경유 없이 처리한다.
모델·상태는 자주 바뀌므로 문서에 적지 않고 **배정 직전 `coord status` 출력을 유일한 기준**으로 쓴다.

| pane | 라벨 | 역할 |
| --- | --- | --- |
| `w18:p1` | o | 오케스트레이터 |
| `w18:p2` | w1 | 레터 구현·검증 |
| `w18:p4` | w2 | 감사·조율 (0.3.x 중단·WIP 보존) |
| `w18:p7` | r | 리뷰 전담(독립 판정·최종 리뷰) |

리뷰는 r 중심으로 진행하고 과부하 시 독립 검증을 워커에 분산한다. 모델·effort 확인 기록은 [재개 기록](insights/union-handoff-resume-20261021.md)을 따른다.
## 메신저 역할

1. 사용자 요청을 컨텍스트·현 상황과 함께 오케스트레이터/리뷰어에게 전달하고 필요시 직접 처리한다.
2. 환경변수·비밀값·인프라·결정·PR 승인 등 사용자가 해야 하는 조치를 확실히 전달한다.
3. 컨텍스트를 반영한 질문 보완·상세화 외 업무는 오케스트레이터에게 위임한다.
4. 오케스트레이터의 사용량 초과로 인한 작업 불능을 확인하고, 필요시 적절한 기존 워커/리뷰어를 오케스트레이터로 승격해 인계한다. 다른 역할 재배분에도 대응하되 모델·세션은 사용자 결정을 따른다.
5. 지시할 때 **분배를 가정하지 않는다.** 지금 쓸 수 있는 워커 목록(라벨·pane id·화면 모델·상태)과
   제약을 함께 보낸다. 누구에게 어떻게 나눌지, 누구를 리뷰어로 둘지는 오케스트레이터가 정한다.
   워커가 늘거나 줄었을 수 있으므로 목록은 지시 직전에 읽은 값으로 적는다.

## 오케스트레이터 역할

o는 분배·진척·막힘 해결·우선순위를 맡는다. 구현·긴 검증·리뷰는 워커에게 넘기되, 패킷 왕복보다 빠른 조회·문서 읽기·
git/gh 단일 조작(PR 생성·CI 확인·위임된 머지)은 직접 한다. **리뷰는 구현자와 다른 에이전트가 맡는다.**

1. 메신저의 작업을 워커에게 분배하고 요구·소유 파일·완료 기준을 docs·패킷으로 전달한다. 5분 단위로 나누되
   앞 단계 결과가 다음을 바꿀 때만 단계를 나눈다. 독립 작업은 idle 워커 전원에 병렬로 준다.
2. 느린 워커의 요금제·환각·비효율·권한 문제를 확인해 해결한다. 사용자 조치는 메신저에게 전달한다.
3. 리뷰어의 PR 발행 여부를 백그라운드로 감지해 종료를 판정한다. PR 발행은 머지 승인이 아니다.
4. 가능한 작업을 쥐고 있지 않는다. 긴 테스트·빌드는 백그라운드·기존 워커로 유도한다. 서브에이전트·새 패널은 쓰지 않고 기존 패널 안에서 재배정한다.

## 워커 역할 (2개 이상)

1. 진행 중 주요 내용을 docs에 보고하고 최종 의견·분석은 허가된 범위의 issue에 남긴다.
   외부 기록이 허가되지 않았거나 원격이 없으면 [tasks.md](tasks.md)에 기록한다.
2. 복잡한 판단을 먼저 하지 않고 단위테스트·요청/문서 일치도를 확인한다. 상세 판단은 리뷰어에게 넘긴다.

## 리뷰어 역할

- 워커 결과를 평가·판단한다. 작은 문제는 직접 개선하거나 오케스트레이터에게 재분배를 요청한다.
- 큰 문제가 없으면 dev → main PR을 발행한다. main 직접 push는 금지, CI·리뷰 통과 PR은 머지 후 사후 보고한다.
- 외부 기록은 root 독점이 아니다. 워커의 issue 기록·리뷰어의 PR 발행도 사용자 허가 범위에서 수행한다.

## 배정·권한·중단

- 같은 파일을 동시에 두 작업에 배정하지 않는다. 현재 소유표는 [tasks.md](tasks.md)에 둔다.
- 배정 전 `herdr agent list`와 visible 화면으로 실행 중 모델·상태·한도 문구를 확인한다.
- 워커 모델·세션은 사용자가 정한다. 종료·재시작·모델 변경은 사용자 명시 요청 시에만 한다.
- 권한 프롬프트·요금제 문제는 오케스트레이터가 임의 승인하지 않는다. 필요한 조치를 메신저를 통해
  사용자에게 전달하고 가능한 기존 워커에 재배정한다. 비밀값은 이슈·로그·커밋에 노출하지 않는다.
- memo 이슈는 사람 전용으로 수정·생성·라벨 부착·close하지 않는다.
- 중단 시 새 작업을 시작하지 않고 해당 작업의 워커·백그라운드 실행에 중단을 전파한다.
- 임시 체크포인트는 레포 `tmp/`(gitignore, `.gitkeep`만 추적)에 만든다(`stop_checkpoint.py create tmp/stop-checkpoint-<날짜>.md`). docs/에 만들지 않는다. 기존 파일은 덮어쓰지 않고 새 이름 또는 사용자 확인 후 `--force`를 쓴다.
- [session-handoff.md](session-handoff.md)는 커밋되는 인수인계다. 다음 세션에 필요한 결정·남은 작업만 옮긴다.
- 체크포인트의 `재개 금지`는 사용자 명시 재개 요청까지 유효하다. 재개 시 현재 요청 범위만 수행한다.

## 패킷·보고서 경로

| 항목 | 경로 |
| --- | --- |
| 작업 패킷 | `tmp/<task_id>-packet.json` (레포 루트 기준) |
| 워커 보고서 | `tmp/<task_id>-report.json` (패킷 `report_path`) |

- `task_id`는 `yoroi-` 접두어를 쓴다(예: `yoroi-orch-docs`). 사용자 지정 패킷 ID·보고 경로를 우선한다.
- `tmp/` 파일은 임시다(gitignore). 커밋하지 않으며 진행 내용은 docs, 최종 의견·분석은 issue에 남긴다.
- 보고서 생성·blocked·한도 감시는 아래 스크립트로 한다. 리뷰어 PR 발행 감시는 별도로 수행한다.

```bash
python3 .agents/skills/agent-coordination/scripts/coord.py watch w2 w3 \
  --reports tmp/yoroi-<task>-report.json --interval 20 --max-polls 120
```

## 분배 CLI (coord)

- 분배·전송·감사는 `coord.py`를 우선한다. `herdr agent list`·화면 읽기 등 읽기 전용 조회는 직접 해도 된다.
- o 질의·인계 메시지는 요소식(전달=task/files/constraints/done/report, 회신=status/evidence/result/next)으로 주고받으며 인사·산문·문맥 반복을 넣지 않는다. 규칙 근거는 [coordination-rules](../.agents/skills/coordination-rules/SKILL.md) 9항.
- 키 입력·세션 조작은 메신저(코테츠)에게 요청한다. 로스터 표는 1열 백틱 pane·2열 라벨 계약을 유지한다.
## 배운 점 (기존 운영 기록)

- 상태 문서 갱신에서 버전 줄·재번호·이동 이력이 누락됐다(2026-10-11·12). 머지 전 버전과 삭제 줄을 대조한다. watch_workers.sh의 LIMIT·BLOCKED는 패킷 문구나 순간 상태로 오탐할 수 있다. `agent get`과 visible 화면으로 확인하고, 반복 오탐 시 보고서 생성만 기다린다. 보고서 생성은 전체 작업 종료와 구분한다.
- 작업 중 pane은 `herdr agent read --source visible`로 읽는다. 라벨(`o`·`w1`·`w2`·`w3`·`r`)은 w12(yoroi)와 다른 워크스페이스 양쪽에 있어 workspace_id(pane의 `:` 접두)를 먼저 확인하고 `--workspace <id>`로 지정한다.
- zsh는 따옴표 없는 `$x`도 단어 분리하지 않는다(`set -- $x` 빈 전송, 경로 묶음 `ls $R` 감시가 0건으로 무한 대기 2026-10-16). 여러 값은 직접 나열하거나 배열로 쓴다.
- 2026-10-08 임의 종료·재시작·키 입력으로 모델이 바뀐 사고 이후 모델·세션은 사용자 결정으로 유지한다.
- 근거 산출 스크립트가 렌더 경로 옵션(가격·previousRanks·excludeModelIds·toRankedRecords)을 빠뜨리면 레터와 결괏값이 어긋난다(2026-10-13, p9). 산출물은 레터 Top10 일치 여부를 먼저 대조한다.
- 동시 작업 중 비소유 파일이 바뀌면(예: model-id.ts 분리) 패킷 소유 목록을 즉시 좁혀 재발행한다. 눈으로 확인한 소유 상태를 믿지 않는다.
- 리뷰어 모델 capacity 오류 시 결과 보고 전에 정지한다. 중간 확인값은 화면에서 회수하고 사용자에게 알린 뒤 재배분을 받는다.
- 2026-10-19 #188: 워커 "집중 테스트 62건 통과" 보고 뒤 오케스트레이터의 전체 `pnpm run check`에서 7건 회귀가 나왔다. 렌더·출력 경로를 건드리는 패킷 완료 기준에는 집중 테스트 대신 전체 check 통과를 넣고, 커밋 전 워커가 전체 check를 돌리고 다른 워커가 리뷰한 결과를 오케스트레이터가 취합한다.
- 2026-10-19 #180: 경로 지정 add에서 같은 단원의 수정 파일을 누락해(#b61f105 수정, #191 CI 2회 실패) CI가 구버전 소스로 돌았다. 커밋 직후 `git status --short`가 비었는지와 커밋 내용 vs 보고서 modified_files 일치를 확인한 뒤 push한다.
