# 0.2.0 구현 계획·패킷 후보 (2026-10-08)

> **0.2.0 보류 (사용자 결정 2026-10-08)**: 0.1.x 마무리 우선을 위해 0.2.0 작업을 보류한다. milestone #2 및 하위 이슈 #30–#55는 open 상태를 유지한다.

- 근거: 이슈 #30–#55(gh view)와 `../yoroi-0.2.0/docs/v0.2.0/*.md` 설계 초안(읽기 전용). 구현·설치 없음.
- 전제: 0.1.0 CLI 회귀(`once`/`watch`) 유지, 단일 수집 주체, 비밀값·원문 미저장.
- 각 단위는 10분 이내 검증 가능한 패킷 후보이며, 소유 파일은 후보다(확정은 패킷 발행 시).

## 의존 순서

1. **기반 #31·#32**: 이벤트·아키텍처 계약 → 서버/웹 빌드 진입점·CI.
2. **저장·캐시 #33–#36**: SQLite 스키마 → 저장 포트 → TTL/LRU 캐시.
3. **수집·조회 #37–#38**: 수집기→저장 연결 → 이력 조회·집계.
4. **상태·API·WS #39–#44**: 상태·재시도 → 기준선 → REST/Zod → 보안 → WS.
5. **웹 #45–#51**: 화면 기반 → 데이터 연결 → 카드/탭/차트/기준선 → 재연결.
6. **운영 #52–#55**: PM2 → 로그 회전 → E2E → 배포·백업 문서.

## 착수 순서 (첫 3단위)

1. **#31 이벤트 계약 타입 (진행 중)**: `usage.collected|partial|auth.expired|resetChanged` DTO 타입과
   `UsageSnapshot` 비노출 규칙을 순수 타입으로 확정. 진행 중 파일: `src/app/collection-events.ts`(타입·생성 함수),
   `tests/collection-events.test.ts`. Zod 도입은 다음 단위.
2. **#31 Zod 스키마 연결**: 위 타입을 Zod 런타임 스키마로 옮기고 파싱 경계 테스트 고정.
3. **#32 빌드 기반**: `src/server/main.ts`·`web/` 진입점과 스크립트/CI를 열어 서버·웹 typecheck·build·smoke 연결.

## 공통 규칙

- 단위 완료마다 `pnpm run check`와 `python3 scripts/validate-repo.py`를 실행하고, 문서는 파일당 100줄 이하.
- 서버·웹 파일 추가 시 `tsconfig.json` include 확장만 하고 버전(Node 24.13.1·pnpm 12.10.1)은 유지한다.
- `ci-scope.py` 분류는 변경하지 않는다. 서버·웹 파일은 자동으로 full 경로에 포함된다.
- 미해결 의존: #29 안전 확인 전 Claude 자동 폴링 금지(#37·#40·#52), #13·#14 미실측 계약은 실측 전 추정 금지.
- 사용자 확인 대기(설계 README §3): Upgrade 없는 GET `426` 유지 여부, DB kind dot 표기.
