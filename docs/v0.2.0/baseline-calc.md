# 한도 초기화·사용 속도 기준선 계산 (#41, 설계 초안)

> 준비 단계: 설치·구현 금지. 근거: #30(확정 창만 선형 기준선), #31 계약 §4.

## 1. 적용 조건 (확정 창만)

- 시작·끝이 모두 확정된 창에만 `경과시간/총기간×100` 기준선을 적용, 0~100으로 제한.
- 시작 확정 = `resetAt` 존재 + 기간 종류 판정 가능. 하나라도 불명확하면 미표시.
- rolling 등 시작 불명확·`resetAt` 미제공은 기준선·소진 예상 모두 '정보 없음'.
- 만료된 창(`now > resetAt`)은 기준선 100 고정 표시가 아닌 '정보 없음'으로 전환.

## 2. 기존 로직 분석 (domain/app 재사용 대상)

- `ui/cli/expected.ts` 인용: `quotaKind`는 id 내 monthly/weekly 토큰,
- codex `10080m` 매칭. `selectExpectedWindow`는 monthly 우선·weekly 차선.
- `expectedPercent`: weekly는 `resetAt−7일` 시작, monthly는 달력 역산 시작,
- 경과율을 0~100으로 제한. `format.ts`의 올림 표시·`formatTimeLeft`는 표시층 유지.
- 재사용 방향: 종류 판정·기간 계산은 domain 순수함수로, 창 선택은 app 정책으로,
- `expected=` 문자열 조립·접미사는 ui 표시층에 남김. infra·서버는 계산 duplication 금지.

## 3. 차이·소진 표시 규칙

- 실제 사용률(`percent`) 대비 차이는 `%p`로 반환. 단위 불일치 시 표시 금지.
- 예상 소진: 표본 충분 + 단위 일치 때만. 과도한 추정·외삽 금지(#30).
- 서버-클라이언트 시계 차이: `observedAt` 기준 계산, 허용 오차 밖은 '정보 없음'.
- `resetAt` 변경 감지는 #31 `usage.resetChanged`로 수신, 재계산 트리거로만 사용.

## 4. 정합성 (기존 문서)

- 계약 §4: 모호 window 추정치 미발행 원칙과 동일. 본 기준선도 미발행이 기본값.
- `failure-policy.md`: `stale` 스냅샷으로는 기준선을 계산·표시하지 않음.
- 상태 `needs-login`·`error` 창은 기준선 대상에서 제외, 마지막 정상값 재사용 금지.

## 5. 검증 계획

- 확정 weekly/monthly: 경계(시작·종료·만료 직전/직후) 경과율 0~100 제한 확인.
- 모호 rolling·`resetAt` 없음: 기준선·소진 예상 미표시 확인.
- 시계 차이·리셋 변경·단위 불일치 케이스를 합성 시간으로 재현.
- 결과는 #41에 단위/통합·API·수집 회귀 결과로 기록.
