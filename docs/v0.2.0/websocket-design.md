# WebSocket 변경 알림·재연결 설계 (#44·#51, 설계 초안)

> 준비 단계: 설치·구현 금지. 근거: #30, api-contract §3·§4, #31(읽기 전용 웹).

## 1. 엔드포인트·메시지 계약 (#44)

- `/api/v1/events`에서 WebSocket upgrade. REST와 동일 인증·Origin 규칙(#43).
- Upgrade 없는 일반 GET은 `426` + JSON 오류(api-contract §3). 경로 충돌 없음.
- Zod 검증 필드: `{ type, provider?, at, version }`. 단조 증가 `version` 포함.
- 종류: `usage.collected`·`usage.partial`·`auth.expired`·`usage.resetChanged`.
- 변경 신호 + 안전 요약만. 전체 사용량 원문·토큰·개인 식별자 발행 금지.

## 2. 서버 발행·정리 정책

- 발행 시점: 수집 확정 후 1회. 부분 실패도 1회(`usage.partial`)로 합산 발행.
- 느린 소비자: 백프레셔 상한 초과 시 해당 연결만 정리, 수집·타 연결 유지.
- 송신 실패·연결 종료·서버 재시작 시 구독 해제 + 타이머 정리, 누수 없이 종료.
- 재시작 전 종료 알림 1회. 클라이언트는 이를 전체 재동기화 트리거로 취급.

## 3. 클라이언트 재연결·재동기화 (#51)

- 연결 상태(`연결됨`·`끊김`·`재연결 중`)를 UI에 표시. 끊긴 값은 최신처럼 표현 금지.
- 재연결: 상한 있는 지수 backoff + 지터. 인증 실패 시 재연결 중단 + 로그인 안내.
- 이벤트 수신 시 TanStack Query 관련 캐시 무효화, 본문은 REST로 조회.
- 재연결 성공 후 반드시 `latest`·`providers` REST 재동기화(이벤트 누락 전제).

## 4. 엣지 케이스

- 순서 역전: `version` 비교로 구버전 무시, 역전 시 REST 재조회.
- 다중 탭: 탭별 독립 재동기화, 공유 쓰기·리더 선출 없음.
- 서버 재시작: 버전 리셋으로 간주, 전체 재조회 + 캐시 무효화.
- `auth.expired` 수신 공급자는 `needs-login` 표시, 자동 재시도 금지.

## 5. 검증 계획

- 가짜 소켓으로 upgrade·Zod 거부·느린 소비자 정리·송신 실패 무누수 확인.
- 끊김·순서 역전·다중 탭·재시작·인증 실패 시나리오 + REST 재동기화 확인.
- 결과는 #44·#51에 경계 테스트 + 화면 검증 근거로 기록.
