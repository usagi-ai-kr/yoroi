## 1. 범위·저장소 경계

- [#72](https://github.com/qus0in/yoroi/issues/72)와 같은 파일 `$YOROI_DATA_DIR/yoroi.db`(기본 `${XDG_DATA_HOME:-~/.local/share}/yoroi/yoroi.db`)에
  테이블만 추가한다. 경로·권한(디렉터리 0700, 파일 0600)·연결 정책(`node:sqlite`, WAL,
  `busy_timeout`(Zen 락 2000ms, 캐시·이력 연결 100ms), `schema_migrations` 순차 적용)은 [#72](https://github.com/qus0in/yoroi/issues/72) 구현을 상속한다. 시각은 ISO 8601 UTC TEXT.
- TTL 캐시 `cache_entries`와 영구 이력 `observation_samples`는 테이블을 분리한다.
  캐시 만료·삭제·손상은 이력을 지우지 않는다.
- read-through 규칙(§4 단일 정의): 캐시 미스는 `once`의 앱 조회에서만 기존 공급자 실측을 실행하고,
  이력·Δ 조회 경로는 외부 수집을 하지 않는다. 캐시 저장소 자체는 외부 수집을 하지 않는다.
- 캐시 키·이력·로그 어디에도 API 키·토큰·Authorization 헤더·원본 응답을 저장하지 않는다.

## 2. 마이그레이션 v2 DDL (v1은 [#72](https://github.com/qus0in/yoroi/issues/72) provider_locks/lock_events)

```sql
CREATE TABLE cache_entries (
  key TEXT PRIMARY KEY,             -- §3 키 규칙, 비밀 미포함
  value TEXT NOT NULL,              -- 정규화 성공 스냅샷만 직렬화
  observed_at TEXT NOT NULL,        -- 원래 실측 시각 그대로
  expires_at INTEGER NOT NULL       -- observed_at + 60000 epoch ms
);
CREATE INDEX idx_cache_expires ON cache_entries(expires_at);

CREATE TABLE observation_samples (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  provider TEXT NOT NULL,           -- usage.ts의 5개 provider
  account_scope TEXT NOT NULL,      -- 인증 프로필 단축 해시(원문 금지)
  contract_version TEXT NOT NULL,   -- sourceVersion/계약 버전
  window_id TEXT NOT NULL, unit TEXT NOT NULL, observed_at TEXT NOT NULL,
  period_start TEXT, reset_at TEXT,
  used REAL, remaining REAL, limit_value REAL, percent REAL,
  CHECK(used IS NULL OR used >= 0), CHECK(remaining IS NULL OR remaining >= 0),
  CHECK(limit_value IS NULL OR limit_value >= 0),
  CHECK(percent IS NULL OR (percent >= 0 AND percent <= 100)),
  UNIQUE(provider, account_scope, contract_version, window_id, unit, observed_at)
);
CREATE INDEX idx_obs_latest ON observation_samples(provider, account_scope, window_id, observed_at DESC);
CREATE INDEX idx_obs_reset ON observation_samples(provider, reset_at);
```

## 3. 캐시 키 구성 (비밀 미포함)

- 키: `cache:v1:{provider}:{lookup}:{scope}:{contract}`.
  `lookup`은 조회 방식+입력 정규화(예 `window:5h`, `windows:all`, `history:from..to`),
  `scope`는 인증 프로필 식별자의 단축 해시(SHA-256 앞 24 hex)나 비민감 라벨이다. macOS Keychain 우선 Claude는 인증 1회로 얻은 계정 다이제스트를 `.<digest>`로 덧붙인다([architecture.md](architecture.md)),
  `contract`는 `sourceVersion`/계약 버전이다. provider·입력·프로필·계약 중 하나라도 다르면 다른 키다.
- 자격 증명 원문은 키 재료로 쓰지 않는다.

## 4. TTL 60초 경계와 read-through

- hit 조건: `now < expires_at`(`observed_at + 60_000ms`)이고 `now >= observed_at`. `now < observed_at`(시계 후퇴)이면 miss다.
- hit 응답은 `observedAt`을 원값으로 유지하고 `cacheHit`·경과 초를 표시해 실시간 조회로 오인하지 않게 한다. CLI 프로세스가 재시작돼도 같은 DB에서 hit가 유지된다.
- miss(만료·키 없음·`--refresh`·시계 후퇴)에만 외부 조회를 실행한다. 성공만 저장하고 타임아웃·인증 오류·HTTP 실패는 캐시하지 않는다.
- read-through 단일 규칙: ① `once` 읽기 경로만 miss 시 수집 ② 이력·Δ 조회 경로는 수집하지 않음 ③ 캐시 오류는 miss로 취급(직접 조회, 저장 생략) ④ 이력은 실측 성공 때만 INSERT.
- 같은 키 동시 호출 병합(in-flight)은 구현하지 않는다(해당 없음): watch 제거([#83](https://github.com/qus0in/yoroi/issues/83))로 프로세스당 `once` 1회·공급자당 소스 1개다. 429/`Retry-After`와 호출 간격 정책을 우회하지 않는다.
- 캐시 읽기 오류·파일 손상·SQLite busy 시 해당 provider만 오류 격리하고, 이력·타 공급자에 전파하지 않는다.

## 5. 이력 기록과 변화량·reset 판정

- `observation_samples` INSERT는 외부에서 실제 수집한 성공 스냅샷 경로에서만 한다.
  cache hit는 기록하지 않는다. 중복은 UNIQUE + `INSERT OR IGNORE`.
- 비교쌍은 같은 `(provider, account_scope, contract_version, window_id, unit)`의 직전 실측 행만이다.
  `period_start`/`reset_at`으로 다른 한도 기간임이 확인되거나 contract가 다르면 비교하지 않는다.
- Δ는 **`최신 샘플 − 그 직전 실측 샘플`**로 정의한다. cache hit·miss가 같은 Δ를 보이게 하고, hit에서 자기 자신과 비교해 0이 되는 것을 금지한다.
- **보존·정리(구현값, 상수·설정 불가)**: `once` 종료 시 90일보다 오래된 이력과 시리즈(provider·scope·contract·window·unit)당 1000건 초과분, 만료 캐시를 삭제한다(`src/composition-root.ts`).
  정리 실패는 결과에 영향이 없고 Zen 락 행은 건드리지 않는다. 백업·내보내기는 지원하지 않는다(`yoroi.db` 파일 복사는 사용자 몫).

| 상황 | 표시 | 이력 |
| --- | --- | --- |
| 새 창(초기화, `reset_at`/`period_start`가 이전보다 미래로 이동) | `reset` | 관측 행 저장 |
| `reset_at` 과거 이동·소실, 필수 값 누락 | `n/a` | 누락 사유 코드(읽기 시점 계산) |
| unit·contract 변경 | `n/a` | unit_mismatch, 변환 추정 금지 |
| 비교 가능 | `Δ = 최신 − 직전 실측` | 정상 |

- Δ는 절댓값+부호를 유지한다: `+4.2%p`, `-0.35 USD`, `+1,200 tokens`, 시간차 `+4.2%p / 2h`.
- `percent` 변화는 %p(절대차)이며 백분율 변화율과 구분한다. 모델·공급자의 서로 다른 단위를 합계로 단정하지 않는다.
- **출력 호환**: 평문(`once`)은 기본 바이트 단위로 불변. Δ·캐시 표기(`cache: hit 23s ago`)는 `--pretty` 한정이며 새 열을 추가하지 않고 Usage 칸 접미/푸터 한 줄로 붙인다.

## 6. 캐시 저장소 결정 ([#82](https://github.com/qus0in/yoroi/issues/82) (a) 승인)

- **결정: Keyv·`@keyv/sqlite`·`keyv` 코어를 도입하지 않고, `node:sqlite` 위에 자체 캐시 포트+어댑터를 둔다.**
  저장소는 같은 yoroi.db의 `cache_entries` 테이블이며, 필요한 연산은 `get(key, now)`·`set(key, snapshot)`·만료 삭제뿐이다.
- 근거: 기존 `openDatabase`의 경로·권한·WAL·`busy_timeout`·마이그레이션·종료 정책을 재사용하고 native 의존성(`better-sqlite3` fallback)을 피한다.
  TTL 기준이 "설정 시각+TTL"이 아니라 `observed_at + 60s`라 Keyv 기본 TTL 의미와도 다르다. 공식 `@keyv/sqlite`는 `node:sqlite` 드라이버를 지원하나, 단일 연결 소유권·권한 정책 일원화를 위해 미사용한다.
- 캐시 포트를 라이브러리 독립으로 분리해 이후 교체 가능하게 한다.

## 7. 테스트 계획 (구현 시)

- Node test runner + 임시 파일 DB(0.2.0 §6: OS 임시 디렉터리, 종료 시 `-wal`/`-shm` 포함 제거), 가짜 시계 주입.
- TTL 경계: 최초 요청 → t+59,999ms hit(외부 호출 0회; macOS Keychain 우선 Claude는 인증 읽기 1회·HTTP 0회) → t+60,000ms miss → 재시작 후 hit 유지 → `--refresh` miss → `now < observed_at`(시계 후퇴) miss.
- 계약: 재요청 hit, provider/프로필/contract 키 격리, 프로필 전환 시 다른 캐시, 실패(타임아웃·401·5xx·파싱) 미캐시.
- 이력: cache hit·TTL 만료·캐시 행 삭제 후에도 이력 행 수 불변. 재수집 성공만 행 추가. Δ는 hit·miss 동일.
- 변화량 fixture: 증가/감소, reset(미래 이동), 누락·단위 변경·비교 불가 → `reset`/`n/a`, %p·부호·시간차 표기.
- 출력 호환: `once` 평문 불변(기존 렌더 테스트 정확 문자열), `--pretty`에서만 Δ·캐시 표기.
- 안전·회귀: 0600/0700, WAL·busy_timeout, 캐시 손상·busy 격리, 기존 5개 provider CLI 회귀.
